# Trylo Mobile 第二版设计依据

本轮只制作独立交互预览，保留第一版，不集成正式 APP UI。

## 阅读并核验的资料

- Claude Code Remote Control：https://code.claude.com/docs/en/remote-control 。远程设备继续本地会话；会话列表、电脑图标、在线状态；本机休眠/网络中断后的恢复。借鉴连续会话心智模型，不采用其云端中转架构。
- GitHub Agents panel：https://github.blog/changelog/2025-08-19-agents-panel-launch-copilot-coding-agent-tasks-anywhere-on-github-com/ 。任务列表展示清晰状态，点击进入具体工作。借鉴会话概览与待处理入口。
- Google Material Bottom sheets：https://m3.material.io/components/bottom-sheets/guidelines 。补充内容/操作可放入底部面板；面板由用户动作打开；具备关闭入口；超长内容内部滚动。借鉴按需打开审批与工具详情。

以上是官方网页核验，不是对三家已安装手机应用的实机评测。通用搜索接口鉴权失败后，改用浏览器直接阅读官方页面。

## 对第一版的判断

第一版连接栏、项目、会话标题占据较多高度；审批卡长期占据底部，使小屏正文过短。第一版逐项呈现过程便于跟进执行，第二版收拢工具便于阅读回复。根据用户反馈，两种阅读方式都有价值，保留为可切换模式，共用第二版审批。

## 第二版方案

1. 会话首页：工作空间与电脑在线状态、继续当前任务、待处理入口、近期会话。
2. 会话详情：紧凑标题 + 项目/设备上下文；顶部切换对话模式与过程模式。对话模式将连续工具收拢为摘要，点击进入执行记录；过程模式将同一份消息按顺序逐项呈现，原位展开输入、输出和耗时。结果共用独立入口。默认过程模式，保存主界面选择；切换保留草稿、展开状态和各模式阅读位置，不重启或切换远程任务。
3. 待确认操作：紧凑提示行不挤占正文；主动点开后进入审批底部面板，明确命令、位置、范围、允许本次/拒绝。
4. 连接中断：顶部可恢复提示、保留已有内容；已同步前按钮禁用。发送草稿不因断线清空。
5. 结果入口：文件与最终答复分开，查看文件不需要在历史消息中翻找。

## 视觉约束

配色：纸白 #FFFFFF、浅底 #F5F6F8、正文 #20242B、次要文字 #727984、Trylo 金 #9B7A31、在线绿 #27775D。沿用现有 Trylo 标识。系统中文字体与 Segoe UI，标题 21px、正文 14px、辅助 12px。可操作区域至少 44px，正文左对齐，边框仅用于分隔页面/记录；色彩集中用于状态与主操作。

桌面预览并排呈现对话模式与过程模式，手机只显示一个可导航的完整界面。思考摘要只显示电脑已提供的内容。

## 范围

本机 Gateway 使用生产实现与本轮之前修好的客户端；电脑、会话、任务、结果全部为独立合成数据。第二版端口 4186/49424，不修改第一版 4183/49414 的会话。多会话后台状态、推送、完整逐块事件投影和 Android 实机能力未因此完成。
