# New Trylo CLI 文档放置规则

本目录只服务于新的 Trylo CLI 工程。旧实现、研究材料和可执行代码不得混进文档权威层。

## 三层目录

| 目录 | 放什么 | 不放什么 |
| --- | --- | --- |
| `00-总领/` | 不随单期结束而失效的工程原则、总架构、施工依赖顺序、学习型 LOOP 的讨论/决策记录、质量和许可证政策 | 某次实现日志、临时排障记录 |
| `01-分期施工总技术文档与架构/` | 每一期开始前冻结的目标、架构、接口、任务包、退出标准和风险 | 每日进度、测试原始输出 |
| `02-分期工程产出/` | 按期归档施工中产生的 ADR、审计、测试证据、迁移记录、基准报告和复盘 | 尚未批准的全局规范 |

[`references/`](./references/README.md) 只保留资料导航和来源台账，不是设计权威。第三方 checkout 位于仓库根 `_workspace/research/new-cli-open/`，历史研究报告与来源证据位于 `_workspace/archive/tracked/new-cli-reference-*/`；它们不能被产品代码直接依赖。

## 权威顺序（2026-09-16 更新）

发生冲突时按以下顺序处理：

1. 用户明确决策（学习议题的书面形式：`03-学习意志/` 中符合 `禁止乱放.txt` 的文档）；
2. `00-总领/TRYLO-LEARNING-AGENT-顶层架构与目标.md`；
3. `00-总领/` 中其他已批准且不与顶层架构冲突的分权、质量和依赖政策；
4. 当前期施工总技术文档中不与以上冲突的部分；
5. 当前期工程产出中的审计事实与已批准 ADR；
6. 调研资料和过程记录。

参考资料永远不能覆盖 Trylo 自己的合同。文件名含 `（过程记录-已过期）` 的文档只用于追溯当时为何这样施工，不得成为新工作包的规范性依赖。

## 文件命名

- 总领文档：`主题.md`。
- 分期总技术文档：`Pxx-主题-技术规格.md`。
- 工程产出：`YYYY-MM-DD-类型-主题.md`，例如 `2026-09-10-ADR-事件序列化.md`。
- 2026-11-07 起，新增原始证据、测试输出、运行数据、截图及候选构建统一放在仓库根 `_workspace/` 对应任务目录；本目录保留正式设计、ADR 与验收摘要并链接原始证据。冻结的历史正文与哈希不篡改，搬迁由清单和维护定位表追溯。禁止把密钥、用户私有正文或未经脱敏的模型请求写入文档。

## 文档头

新的架构或施工文档应包含：状态、阶段、负责人、最后更新、依赖决策。状态只允许：`草案`、`待审`、`已批准`、`已替代`、`已归档`。

## 变更纪律

- 已批准的总施工依赖关系才视为冻结；状态为 `草案/待审` 的内容可以按产品讨论修订。调整已批准内容必须写 ADR，说明为何原依赖判断失效、迁移成本和验收影响。
- 工期数字允许依据真实吞吐量滚动校准，但不得用缩短工期删除退出标准。
- 当前期开始编码前，其总技术文档必须达到 `已批准`。
- 当前期结束时，退出标准逐条链接到 `02-分期工程产出/Pxx-*/` 的证据。
- 对外宣称“追平”必须由能力矩阵、黑盒回归和真实平台验证共同证明。
