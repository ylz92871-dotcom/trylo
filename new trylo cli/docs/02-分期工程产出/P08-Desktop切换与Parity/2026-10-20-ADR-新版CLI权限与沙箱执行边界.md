# 新版 CLI 权限与沙箱执行边界

状态：代码与制品验证通过
阶段：P08
负责人：本轮实现者
最后更新：2026-10-20
依据：用户要求全面修复新版 CLI 工具权限和沙箱误拒绝；保持 Permission Service 唯一授权者。

## 合同与故障

- Desktop 的 unrestricted 不能被另一份固定 workspace-only 路径配置悄悄覆盖；ask/workspace_write 对工作区外操作应交给宿主逐次审批，read_only 继续禁止写入。
- 增加显式 `--filesystem-access workspace|reviewed|host`，默认 workspace。范围只决定哪些目标可进入审批，不改变 Windows ACL/UAC，也不自动改变 OS shell isolation。
- 增加显式 `--shell auto|none|bash|zsh|sh|powershell|cmd`，Desktop 非只读运行选择 auto。独立 CLI 未传参数时保留现有设置和直接执行合同。
- 外部文件读取必须通过调用级权限，不把读取文件正文或目录枚举放在审批之前。额外审批要求只会增加检查，不能减少原工具的 needsApproval；不改变工具 schema 或 catalog hash，避免破坏既有会话恢复。
- 同一文件范围传递到准入、实际读写、补丁和 shell cwd；不能只放开第一层而在执行时再次硬拒绝。
- 默认路径、拒绝、取消、只读、设备路径、链接越界反例必须保留。学习、MCP 包级禁用与安装权限不变。

## 决策与架构

路径范围、解释器、OS 隔离、调用授权分别由明确配置选择。`FileAccessMode` 住在不认识工具和 MCP 的 `ports/filesystem.ts`；工具端口继续提供兼容类型导出。PermissionPort 只借出当前显式拒绝的事实；模型、历史记录、学习和工具执行器不能写入它。

| 选择 | 文件目标 | Shell | 调用授权 |
| --- | --- | --- | --- |
| 独立 CLI 默认 | workspace，保留真实路径包含检查 | 现有设置；未配置时 direct | 保留原默认策略 |
| Desktop 只读 | workspace | 禁止 run_shell | 禁止修改；工作区读取保留 |
| Desktop 每次审批 | reviewed | auto，显式 host 进程边界 | 修改、命令、外部读取逐次审批 |
| Desktop 自动编辑 | reviewed | 同上 | 普通工作区编辑自动；命令、删除、外部目标审批 |
| Desktop 完全自动 | host | 同上 | 宿主自动批准；包级禁用和系统权限仍有效 |

reviewed 对工作区内路径继续验证真实包含关系，拒绝借局部 junction 越界；用户可以明确给出外部目标后审批。host 可解析链接的真实目标，但同样通过调用权限。OS 的 host 边界仅采用调用者已有权限，不运行提权，也不修改用户账户。

### 贯穿的修复

1. 新参数从解析、prepared session、每轮 host、sandbox policy 到所有文件执行器贯通，包括 Notebook/PDF 的二次分派、补丁、Shell cwd/stdoutFile。独立 CLI 的命名读取工具可以通过 allow/deny 列表显式控制外部访问。
2. 外部只读工具增加调用级审批，静态 schema/needsApproval 不变；MCP 组合沙箱和两种子任务 worker 继承同一额外审批要求。普通工作区读取不新增提示。
3. Desktop 的包级拒绝最先保留。V1 外部读取请求不能被工具包泛化的“read 自动允许”规则覆盖；批准/拒绝后才读取数据。
4. 显式拒绝优先于历史精确调用批准、exec policy 自动允许、reviewer 和沙箱升级；直接执行入口也检查同一拒绝事实。保持静态工具存在性，避免 `--tools` 与 `--deny-tools` 并用时误报未安装。
5. 启用真实 Shell 时同步提供实际解释器的描述；支持其变量、重定向、管道。`none` 保留直接执行，未安装的指定解释器给出明确失败。tool schema/catalog identity 保持不变。
6. 工作区根保存物理路径及原拼写别名；别名内绝对路径映射回冻结的物理根。别名被重新指向后不扩大旧工具实例的范围。以 `..` 开头的普通目录名不再误判为父级遍历。
7. 外部图片经批准并校验后，当前会话只保存“路径、哈希、大小、detail”的内存能力。provider 取得只读解析端口，发送前重新核对内容；warm 缓存只复用 transport，不保存另一轮的授权。历史记录单独携带的引用不能授权外部读取，会提示重新 view_image。别名图片固定到已解析的物理目标。
8. 导航搜索的外部目标有独立相对路径空间；目录审批不沿子文件链接读取别处。辅助 `.gitignore` 读取也受所批目标的真实路径边界约束，不能借规则读取父目录或逃逸链接。
9. 宿主审批附上实际目标路径、命令和 cwd，复用已有卡片展示合同；不读取待批准文件，也不把拟写入正文放入预览。

为满足既有 400 行约束，将执行选项类型和原有 method 组合函数机械移出入口文件；method 开关、存储与学习行为不变，没有增加依赖。

## 自审与边界

按技能要求审查：可读性、维护性、依赖方向、成功/失败/取消、授权、安全供应链和证据。修正了重复路径权限配置，执行范围由单一 sandbox policy 下传；未扩大 dependency closure。没有让学习写入授权，未改变默认独立 CLI 的隔离选择。

Windows 严格 Shell 隔离仍要求已有可用 SRT 环境；环境故障明确拒绝并给出修复/显式 host 启动指引，不自动降级。受限账户自身的系统 ACL 拒绝不能被产品授权替代。PDF 本轮验证了路径可达与元数据读取，未宣称 Poppler 渲染验收。

当前验证证明本地模拟服务下的实际子进程与文件效果，未建立真实模型普遍可靠性、安装 GUI、任意电脑工具输入或手机真机验收。旧 CLI 的立即 EOF/libuv 退出问题沿用前一版已知限制，本次没有宣称修复。

回滚：撤回本次源代码提交及 Desktop 的 filesystem/shell 参数映射，恢复前一版运行时；不迁移或删除用户会话，不修改全局配置。新类型与额外字段均为可选，静态工具 schema 未变。
