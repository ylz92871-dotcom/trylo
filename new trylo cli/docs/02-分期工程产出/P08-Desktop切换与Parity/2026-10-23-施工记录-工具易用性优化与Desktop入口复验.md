# 工具易用性定向修复与 Desktop 随附入口复验

> 状态：已归档  
> 阶段：P08 Desktop 切换与 Parity  
> 负责人：Codex  
> 最后更新：2026-10-23  
> 依赖决策：用户要求直接优化实际调用中发现的问题；沿用 Permission Service 和 Trylo Protocol 边界。

## 行为与修复

1. **命令说明统一。** 最终目录原本已有 shell 模式适配，不能把全部 Desktop 调用说成无 shell。此次复用已有 execution-description 模块，统一实际 shell、参数文案、超时、后台使用方法和已安装程序限制；显式缺失解释器会带 shell_not_installed 等原因码。没有新增第二套模式判断，也没有切换用户设置。
2. **默认超时 10 秒改为 60 秒。** 显式 timeoutMs 的 1–120000 毫秒范围保留。长任务在运行前就提示使用 runInBackground，然后按 sessionId 轮询。超时仍是失败并终止进程，不会自动重试。超时和非零退出均说明成功完成的前序步数、当前失败命令、后续步骤未运行，以及可能存在部分效果；此前各步的输出仍保留。
3. **中断调用历史闭合。** 执行准入与恢复共用同一个成功响应判定。对 EOF、网络中断和 length 等未接受响应，本次响应中已组装但尚未派发的调用会落盘为 failed，注明 not executed；之前已经完成的工具结果保持原样。新增结果通过现有增量持久化出口写入，续接请求得到有效的调用/结果配对。用户取消沿用原有取消合同。整体 unknown/failed 终态和已有权限审批继续成立。
4. **PowerShell 后台启动修复。** 实验发现旧代码用 shape.kind === shell 判断无 steps 的解释器命令；该字段实际表示 Windows 引号处理，PowerShell 和 POSIX shell 同样可能使用 direct。因此 PowerShell 后台任务被错拒为 empty_command。修复后转交已批准 argv；后台 pipeline/steps 拒绝规则保留。
5. **旧会话兼容。** 两个参数的说明变化会进入既有目录哈希。兼容投影只还原旧说明，同时保留当前结构、边界和权限字段；不要求用户为纯说明变动迁移旧会话。真实进程验证从旧编译版本创建会话，再由新版本续接成功。

## 验证证据

- 固定候选完整 11 步门禁 ALL PASS，4421 项 hermetic 测试、38 项合同检查；独立 Windows 后台进程检查 2 项通过；Desktop 适配层 44 项通过。
- 最终 12 项定向用例对旧产物运行：11 红、1 个既有模式适配控制用例绿；修复后 12 绿。PowerShell 后台旧版红、CMD 控制绿；修复后两者均绿，并核实真实退出码 7。
- sandbox 默认路径由真实 CLI 进程和本地脚本化 HTTP 端点验证；Desktop 路径使用随附 CLI、随附固定 Node、stdio 审批和 host shell 隔离模式复验。
- 前台脚本实际等待 11 秒并只写入一次；后台 PowerShell 实际等待 12 秒、沿原 sessionId 轮询后退出 0，并只写入一次。中断用例先完成一次写入，再切断含另一调用的响应；终态保持 unknown，续接请求包含“未执行”的结果，物理写入总计仍为一次。
- 这些是定向进程验证，不是另一轮持续一小时的真实模型长任务。脚本化端点不证明真实模型采纳说明的概率或思考延迟改善。

## 集成失败与纠正

首次隔离基线因测试副本缺少两份 WP-C 文档及独立 Git 索引失败；补齐验证环境后复验。实现中曾出现测试跨层导入、旧默认值断言未更新，以及兼容投影的 readonly JSON 收窄编译错误；原始负例日志均保留，最终固定候选全门禁通过。

首次随附入口复跑启动失败。原因是本次同步的 stream-projection 包含基线已有的 subagent-budget 协议校验导入，而我同步时漏带其编译产物。这是本轮集成遗漏，不能计为原有工具缺陷。补齐该无依赖纯校验模块的 JS/d.ts，源文件字节未改，然后重跑随附入口与库存检查通过。失败 stderr 保留。

依赖检查包含静态导入与字面量动态导入。Windows vendor 原有 CA/MITM 延迟入口按既有 copy-vendor 静态闭包合同不分发，检查结果单列 optionalNotPackaged；本次没有扩展该功能或供应链。
