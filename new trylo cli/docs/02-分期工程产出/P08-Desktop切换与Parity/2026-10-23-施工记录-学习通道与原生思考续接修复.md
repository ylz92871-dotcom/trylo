# 学习通道提取后的原生思考续接修复

状态：本轮修复与开发制品验证完成  
阶段：P08 Desktop 切换与 Parity  
日期：2026-10-23  
依据：用户要求继续实验调研、纠错并修复；遵循 trylo-code-quality，保留已有脏工作树及并行变化。

## 新发现与对照

前一轮的纯文本/短工具任务不能排除学习通道与原生续接交叉的问题。本轮以相同原生思考、文字、工具调用作控制：不开提取时续接正常；开启学习卡提取后，公开文字从原始围栏变成清理后的正文及一句总结，续接随之丢失。三个独立通道（教学卡、工具缺口、方法反馈）都有该问题。

根因是身份不一致：供应商适配器在原始响应结束时保存原生思考，并用原始正文+有序工具调用建立身份；Loop 的提取通道随后修改公开正文，下次请求使用的是处理后的正文。两者不匹配，原生字段不再加入请求。旧逻辑又无法把未知的新身份归为已证实损失，因此没有降级提示。这是确定的续接缺陷；不能从此直接推算额外思考 token 或总耗时。

六个新回归在未修复制品上全部失败，覆盖三通道各自的同进程和恢复路径。真实 Desktop 固定 Node/CLI、预置单张方法卡、两次 OS 子进程的本地严格模拟接口，也复现了同一问题：第一次实际读取后丢续接，接口拒绝；换进程恢复仍因同一字段缺失失败。此实验不是外部真实服务证据。

## 修复合同与边界

ProviderContinuationPort 增加可选 bindCanonicalResponse：只接收本次已完成响应经可信通道处理后的 assistant 身份，不接收原生思考。Loop 在 finish 已被适配器捕获、stream_end 尚未耐久保存时调用，且仅在存在提取通道、绑定 scope 及相应能力时工作。普通关闭学习的路径不构造新消息身份。

原生适配器校验当前 scope、已完成 checkpoint、assistant 角色以及有序工具调用（含归一化前的原始参数）完全一致，才替换正文身份。只替换缓存最后一个精确对象，原生思考及其字符额度保持不变，不追加重复项、不额外驱逐历史。native/absent/rejected 分类保持原样，拒绝态不能借此变回原生态。随后复用现有 v2 序列化写口，恢复读取格式不变。身份确认先于原 stream_end 的耐久记录，没有第二个 session writer。

生产范围为 ports/provider.ts、loop/stream.ts、glm-continuation-cache.ts、glm-tool-continuation.ts 四个模块，新增一个六项回归文件。核心依赖仍朝向端口，没有导入学习持久层或供应商实现；学习提案、审批、权限和副作用执行入口均未扩展。可选新方法不要求旧 ProviderPort 实现迁移，CLI v1 事件和磁盘格式未变。

修复对新产生的响应生效。既有日志里已保存的错误原始正文身份继续按原合同读取，不猜测匹配，不批量重写历史。32 项/字符上限的既有缓存策略也没有在本轮扩大，不能据此宣称无限长会话可靠。

## 验证结果

- 新回归 6 项由全红到全绿；每项还检查错误 scope 和不同工具身份不能改写 checkpoint。
- 候选与更新后随附制品的同一组回归均通过。
- 两个真实 CLI 子进程的本地严格接口实验由失败变为两轮 completed，各实际读取一次、答案均为 DONE；第四次请求同时正确带回两轮的续接，公开正文不含隐藏反馈。
- 冻结修前基线完整 11 道检查通过，4,318 个测试条目；修后原始 11 道检查全部通过，4,324 个测试条目，合同测试 38 项，耗时 318.20 秒。没有修改门禁脚本、阈值或依赖。
- 开发 dist 和 Desktop 随附 CLI 仅同步四模块 JS/声明共八个输出，2818 项文件清单校验及更新完成，逐输出绑定冻结源码。旧模块和清单保留在 publish-before。没有更新安装包或验收 Tauri/WebView2 原生界面。

真实火山使用本轮获准的临时凭据、Coding Plan ark-code-latest；业务输入为合成算术、生成文件及预置学习卡，思考档位显式 high，以观察非空思考，并要求工具前输出合法反馈。它不是默认档位性能样本。首组真实响应中 2 次同时出现学习反馈围栏、工具调用和原生思考；后续请求 4 项原生摘要核验全部一致。该组最终格式未通过，不能记为整任务 PASS。 首组一次最终反馈标记放错行，按现有“非法围栏原样可见”合同显示；另有合法尾换行使最初的严格字节 oracle 失败。第二组把格式要求逐行明确，并按 trim 后的答案核对，但第二轮没有重新读取同一个未变化文件；该组也没有记通过。

这暴露了实验设计缺口：固定 DONE 不依赖实际文件内容，模型可能复用旧结果。第三组改为每轮新建不同文件，放入未在提示词中披露的新随机校验串，要求返回实际读到的串。两个进程各读取一次，两个校验串准确，四项原生续接摘要一致；本组模型未产出反馈围栏，因此它证明真实读取及恢复，不是本轮交叉条件的独立全链验收。三组不得拼成一次整体通过，也没有通过放宽产品解析器吞掉非法围栏。模型的格式遵循与重复读取遵循仍有负例。

实际模型为 deepseek-v4-1-flash。只归档模型、状态、用量、围栏是否出现及摘要，不公开密钥或原始思考。不能声称用户原始长会话已全部复现或全部长思考解决。

## 环境纠错与自审

初始隔离 Git 压缩和 Node 编译遇到机器提交内存不足；原始失败保留。384MB 旧堆额度又不足，记录保留；改为仅此验证进程及其子进程使用 768MB/8MB 半空间后，原始基线和修后门禁完整通过，未降低检查。只终止了已确认属于本轮的失败验证进程树，没有停止用户进程。准备阶段还修正了测试 writer 构造参数和引号；一次真实接口探针在门禁清理 dist 时启动，因入口不存在而未发出请求，其原件留在工作区，最终只验收门禁完成后的随附制品。

按可读性/维护性 → 架构 → 正确性 → 权限 → 并发恢复 → 性能 → 依赖顺序作者自审通过：Loop 只确认可信公开投影，适配器仍是原生状态的唯一所有者；替换必须匹配当前实例及工具身份，失败和取消不会制造 checkpoint。新分支每次响应最多一次，缓存计数及原生字节不增长。没有新增依赖，也没有绕过学习审批。此为作者自审和执行证据，不称独立第三方审计。
