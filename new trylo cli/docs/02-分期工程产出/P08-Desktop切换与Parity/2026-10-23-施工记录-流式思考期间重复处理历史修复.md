## 问题与修复

`flushProgress` 已经只提交新增 envelope，但每次收到文字或思考 delta，仍把整份 transcript 交给记录器。记录器为判断是否重复，会重新 JSON 序列化历史条目。长历史在流式输出期间不断重复处理，是一个当前可复现的本地开销；这些字节不是重新发给模型的 token，也不是重复写入磁盘的字节。

修复在 Engine 内保存最后获得成功写入确认的不可变 transcript 引用。未变化的历史不再重复提交，新的 envelope 照常保存；替换、追加、恢复或有序号缺口的 transcript 仍交给既有记录器检查。引用只在成功 ack 后更新，失败不消耗待保存的历史。流式闭合块继续走原路径，副作用前保存意图、结果确认、半截输出保存及错误终止合同保留。

生产修改只有 `internal/loop/progress.ts` 和 `runner-engine.ts`。新增两项回归在 `progress-transcript-cost.test.ts`；既有取消测试改为按序号累计已确认事实，验证实际保存的工具结果，不再要求最后一次 flush 重复完整历史。没有增加依赖、协议字段或磁盘格式。

## 固定输入验证

合成 provider 输入包含 294,912 字符历史、768 段共 98,304 字符思考以及一个工具调用。执行使用真实 Loop、TurnRecorder 和每次追加均 fsync 的 NDJSON store。完整门禁结束后，按前→后、后→前、前→后的顺序单独重跑三组。

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 历史提交次数 | 781 | 4 |
| 提交给记录器的 transcript 文字/输出字节合计 | 231,409,230 | 1,572,888 |
| 首个工具实际启动的中位时间 | 8,180.020 ms | 7,067.277 ms |
| 整轮中位时间 | 8,267.012 ms | 7,149.263 ms |

六次运行的完整 journal、transcript 和 envelopes 的 SHA256 分别一致。工具执行前现场读取 journal，确认已有 `effect_issued`；恢复出的 transcript 与返回结果精确相同。重复提交字节减少约 99.32%，它是本地边界处理量的变化，不能当成模型 token 或整产品提速比例。

与门禁并行的首组测量也保留：修复前约 9.625 秒、修复后约 11.361 秒，不纳入上述单独重跑的时间中位数。磁盘同步和宿主负载仍影响时间；本组只证明固定输入下的本地工作减少，没有证明模型推理速度或思考 token 减少。
