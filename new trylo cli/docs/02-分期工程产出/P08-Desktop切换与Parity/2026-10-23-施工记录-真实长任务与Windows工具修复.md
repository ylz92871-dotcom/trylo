## 任务、冻结与验收方法

用当前 Desktop 随附 CLI 的完整冻结副本运行真实火山任务。先校验 2822 项制品清单，再复制全部 CLI 和依赖；固定随附 Node 字节并记录全局 provider/config/credential 文件哈希。真实接口为 Coding Plan 的 ark-code-latest，实际响应 deepseek-v4-1-flash；启动前预检 HTTP 200、回答 OK。临时凭据只经进程内存和子进程环境使用，命令参数、源码、配置与公开证据不含密钥。没有改全局模型选择或新增依赖。

合成项目包含六个存在明确缺陷的 ESM 模块、8 项原始测试、12 个 CSV 分片与 60 条记录，覆盖 BOM、LF/CRLF、引号逗号、转义、字段换行、严格金额、重复 ID、日期、月份筛选及校验失败时不覆盖旧报告。让模型自行读合同、复现、修实现、跑测试、通过 CLI 生成 JSON/CSV、检查未知 runToken 并写报告。模型不得改输入、测试或 package.json。

每个结束的进程立即保留 first-snapshot，再另复制 audit-copy，由宿主独立重跑测试及 CLI、按生成器的原始结构化记录计算答案，核对实际交付文件。独立检查不能回写模型工作区或首次快照。模型自述、exit 0 和 run_result completed 均不构成通过凭据。

每回合最多 45 次请求、50000 输出 token、12 分钟。初始实验每次请求另限 8192，最终全新任务改为 16384，保留原有总预算。不开学习、不指定思考档位、不安装依赖、不要求子代理。保持 CLI 默认 Windows 隔离与逐次审批，没有以 host 模式绕过隔离故障。此为随附 CLI 的真实进程和工具证据，不是原生 Desktop/WebView2 UI 或安装包验收。

## 首轮失败及三项修复

首轮 15 次真实模型请求、46 次工具调用、232.352 秒。六个项目模块被修复，报告如实说明工具未能运行测试；它仍结束为 completed。独立检查得到项目测试 8/8、重新生成结果正确，但模型没有交付两个计算报告，整体判失败。

### 普通权限保护辅助程序时意外调用编译器

run_shell 在执行命令前报 isolation_helper_protection_failed，PowerShell Add-Type 报缺少权限。最小对照：相同 Node 字节在系统安装路径为 High 进程，原随附副本继承了 Low 标签。按已有 Desktop 准备脚本把随附副本设置为 Medium 后，错误仍可重现。异常堆栈明确落在 System.CodeDom.Compiler.TempFileCollection.CreateTempDirectoryWithAce 和 Win32 CreateDirectory；普通 Medium 平台回归在未修复制品上同样失败。

windows-helper-protection 原来为了读取完整性标签，运行时编译三个固定 Win32 声明。这让本应普通权限可完成的只读观察依赖 CodeDOM 的编译目录创建。现使用仅运行于内存的 Reflection.Emit 定义相同固定调用，使用绝对 SystemRoot DLL 路径并保留 PreserveSig，不生成编译文件、不请求提权。API 用法依据 [Microsoft DefinePInvokeMethod 文档](https://learn.microsoft.com/en-us/dotnet/api/system.reflection.emit.typebuilder.definepinvokemethod)。没有关闭 DACL、所有者、重解析点、可信 writer、Medium/no-write-up 标签和已有标签复用校验；分配的安全描述符及字符串均在 finally 中 LocalFree。

真实平台回归复制测试 Node 并显式降为 Medium，确认 token 为 S-1-16-8192，随后完成目录保护、文件保护和复用。修前失败，修后通过。随附 Node 的完整性标签按已有官方流程准备为 Medium，文件字节保持原 hash，不改全局执行策略、用户权限或系统安装的 Node。

### 隔离代理重新转义了已构造的 cmd 命令行

解除启动阻塞后，npm/npm.cmd 的普通前台调用出现多余引号，含空格的安装路径被截断。相同模型任务通过 cmd.exe /c 的临时调用方式继续推进，首次修复恢复任务的独立产物验收通过；这不等于 npm 正常入口已修复。

windows-shell-boundary 原来把所有单命令直接交给 SRT 的 argv 编码，丢失 CommandShape.shell 所需的 verbatim 语义。现在单个 shell shape 和多阶段流水线共用已有私有 Node runner，在同一个 SRT Job 内用现有 startShellChild/Windows verbatim 机制启动；直接二进制路径保留。私有 runner 接受至少一个已批准 stage，NUL、空 argv 和不合法类型仍拒绝。审批、sandbox planning、环境清理、WFP、ACL 租约和 Job 生命周期未增加执行入口。

真实 SRT 平台测试在修前给出多余引号错误，修后证明空格路径及空格、中文、&、^ 字面参数完整到达，实际写入的 JSON 也一致。私有 runner 单 stage 的退出码和输出回归先红后绿，原多阶段/早退/非法输入检查保留。

### 显式 .cmd 后缀没有固定实际 PATH 位置

进一步的全新任务显示：单写 npm.cmd 虽已通过引号路径，却从工作目录寻找 node_modules/npm/bin，npm 的目录宏没有得到安装目录。无后缀 npm 和显式 .cmd 处理不一致。

executable 的 .cmd/.bat 裸文件名现在通过与无后缀名字共用的 PATH 搜索确认完整目标，再进入原有受控 cmd 构造。含相对目录的显式路径及找不到的名字保留原行为，百分号/控制字符拒绝和引用规则不变。一个真实临时 PATH 文件的形状回归先红后绿；SRT 测试同时验证完整路径和 PATH 裸名两种调用。没有改模型工具 schema 或持久化指纹格式。

生产范围仅四模块：windows-helper-protection、windows-shell-boundary、executable 和 cmd/trylo/windows-pipeline。核心 Loop、Permission、Session、Learning、旧 CLI 和 Desktop UI 源码未修改。

## 完整全新任务与跨进程增量

在全新项目、全新 home/session 和新随机 token 下，最终真实任务用 13 次请求、48 次工具调用、216.363 秒完成。原始测试先被实际复现为 8 项失败，修复后 npm test 8/8；四次非法/缺失/重复参数和缺失输入目录的非零退出是主动负向检查。独立核验：

- 60 条记录、12 个输入文件，总金额 120054 分，5 个分类；
- JSON 对象、CSV 字节、未知 runToken 与独立生成器结果完全一致；
- 原测试、数据、meta、README 和 package.json 均未被模型修改；
- 模型首次交付的两个报告及 REPORT.md 均存在；audit-copy 再生成结果一致。

随后宿主加入 2000 条新记录、更新未知 token，保持旧报告，换 CLI 进程恢复同一耐久会话。增量任务 7 次请求、15 次工具调用、105.078 秒完成，无工具失败。独立检查共 2060 条输入，经月份筛选得到 1540 条、12716943 分、7 个分类，新 token 与两个新文件精确一致；旧 out 两份文件 hash 保持不变，原测试仍 8/8，新增数据和测试未被模型修改。两轮合计 20 次模型请求、63 次工具调用、321.441 秒，是一次全新完成加一次恢复增量完成。

接口观测显示全新任务的首个工具片段等待中位数 1487ms、最大 38679ms，增量任务分别为 7568ms 和 10099ms。全新任务最长工具执行 28291ms，增量为 21357ms，包含每个新进程的真实隔离准备。首工具片段时间包含模型计算和到达该片段的生成/传输，不能纯称“思考时间”；这些样本也不能证明所有长思考消失。本轮的原生续接等值观测未成功匹配历史响应身份，故不据其零 mismatch 声称续接已独立验收。

## 工程检查、实验纠错与证据边界

冻结原始完整 11 项工程门禁通过，4362 个测试条目。第一项修复和前两项修复分别留有完整绿色检查；最终四模块源码的原始 11 项门禁全部通过，4364 个测试条目、38 项合同检查，334.01 秒。指定的回归组 22 项通过，其中 2 项实际 Windows 平台测试单独运行，不把它们混入 hermetic 计数。未改门禁脚本、阈值、依赖或锁文件。

早期实验错误均保留：

- 工具名 search_files 写错，CLI 正确拒绝；留下只有会话头的占用 ID，再用同 ID 新建也按既有合同拒绝。更换实验 ID 后启动，没有删除会话或放松检查。
- 第一次测试夹具在错误 cwd 启动，保留日志后从项目根重跑，8 项缺陷全部复现。
- 第一次运行官方准备脚本漏了其开发启动流程使用的进程级执行策略参数，被本机签名策略拒绝。一次恢复尝试因此仍失败，未记为修复成功；之后按原流程执行成功，未改变系统策略。
- Windows 批处理平台夹具放在私有用户 Temp，下层 Node 入口额外触发父目录 realpath 拒绝；夹具改为与既有私有 runner 相同的 preserve-symlinks 参数，未扩大父目录 ACL。原始失败保留，真实账本项目位于独立 D 盘工作区。
- 一组全新任务被实验的 8192 单次输出上限截断，终态 length/failed，候选工具未执行，没有交付产物。它保留为预算负例，不当成 CLI 截坏参数或首次成功。最终另建 fresh-final，在显式 16384 单次、50000 总预算下完成，二者没有拼成一个通过。

可读性/维护性、架构、正确性、权限、恢复、性能和供应链作者自审通过：复用同一 Win32 调用边界、同一私有 runner、同一 PATH 搜索；没有把供应商或 UI 逻辑塞入核心。Reflection.Emit 的签名固定，API 失败显式拒绝，清理不吞异常。此为作者自审、独立宿主计算和真实进程证据，不冒称独立第三方审计。

只验证本轮所述普通权限保护、前台批处理、直接 Node、真实模型任务和恢复；不外推后台批处理、交互式 PTY、全部提供商或所有长会话。当前源码和开发资源同步也不意味着已经运行的进程会自动加载新字节。

四模块 JS/声明共八个输出仅同步到开发 dist 和 Desktop 随附 CLI，逐项绑定冻结源码；原输出和清单保存在 publish-before。回滚先核对 after hash，再反向应用本轮源 hunk 及本轮输出、清单，不覆盖任何并行或后续修改。所有初始失败、首次快照和隔离会话留在 work/long-task-20261023-r4。

同步后的 Desktop 制品上，指定同一组 22 项回归全部通过，含真实 Medium 进程保护和真实 SRT 批处理参数/文件效果。实际长任务使用的隔离修复副本与完整编译结果逐模块字节一致；开发和 Desktop 各八个输出的 16 项绑定全部核对，2822 项资源清单逐项校验。受保护的全局 provider/config/credential 与 Node 文件字节未变，Node 完整性标签的显式准备另行记录。727 个任务日志、脚本、私有合成会话及公开证据文件共 14624585 字节，临时凭据扫描零命中。没有提交 Git、推送或改安装包。
