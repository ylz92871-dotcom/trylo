# Desktop 权限与双运行时发行修复

状态：已归档
阶段：P08
最后更新：2026-10-20
依据：产品所有者要求深入修复权限问题，发行包默认旧 CLI，设置可切换新版，CoWork 独立。

## 行为合同与根因

审批、进程的 Windows 完整性级别、文件 ACL、命令沙箱和工具可用性是不同事实。批准一个调用不代表另一层已具备执行权限。

1. 新 CLI 的 Windows 执行组合根无条件套用 SRT 受限账户。Desktop 已批准的 shell 仍会因账户未安装、隔离目录授权或环境缺失失败。新增显式命令行选项 `--shell-isolation sandbox|host`；独立 CLI 缺省仍使用原有沙箱，失败不会回退。Desktop 非只读运行明确传入 `host`，由既有 Permission Service 逐调用审批；执行保持宿主已有权限，不请求 UAC，不赋予新令牌。
2. shell cwd 只接受工作区根的绝对路径，误拒绝工作区子目录的绝对路径。现将它作为同目录相对路径的别名，仍执行 realpath、目录与链接包含检查；父目录遍历和工作区外路径继续拒绝。
3. 旧 CLI 只读档位传入空工具目录，连读取工具也无法调用。现保留 Read/Glob/Grep，plan 模式及宿主策略继续禁止写入和命令。
4. 便携启动器只准备四个顶层可执行文件，遗漏 PTY/SRT、ripgrep 等嵌套 helper。现先完整检查五个包内组件目录及 reparse 边界，再匹配启动器已有完整性级别。新增真实 Windows 回归：未修复时嵌套 helper 实际写入 EPERM，修复后精确落盘。不会访问外部工具安装目录或授予新令牌。
5. 旧 CLI 的 `--bare` 强制 SIMPLE 模式，直接移除 Write/Glob/Grep 等工具。真实旧 CLI 黑盒测试得到 `No such tool available: Write`，并非一次审批拒绝。保留 bare 启动，但在既有 Desktop policy 环境标记下复用正常工具目录，继续经过 isEnabled、原有禁用规则、--tools 和 stdio 审批。独立终端的 SIMPLE 目录不变；旧源码仅在主目录提交，公库仅分发其编译兼容制品。
6. Glob/Grep 黑盒测试暴露缺失的 ripgrep 制品及 Bun 编译后指向构建机的 helper 路径。Desktop 改为从实际 CLI 入口旁解析 vendor/ripgrep；补齐官方 Windows 15.2.0 二进制及 MIT/Unlicense 声明，固定官方归档和文件摘要，不依赖系统 PATH。

另修复发行目录污染：Desktop 的 tsc 原本向 dist 输出源文件和测试 JS，单独运行类型检查后可污染已经生成的 Vite 目录。改为 noEmit，生产前端只由 Vite 输出；发行扫描已拦住此前混入的测试夹具。

文件工具工作区边界、禁用工具、MCP 固定工具集和无效输入的硬拒绝保留。`host` 只选择进程执行边界，不是工具授权，不是管理员模式，配置文件或模型参数不能设置它。

## 边界与生命周期

ShellIsolation 由隔离端口定义；CLI 参数在纯解析边界检查闭集，经 prepareRun 传入一次执行资源所有者。运行中的权限和执行边界不受之后的设置改变影响。CLI 领域层不依赖 Desktop 类型。

公库原有独立 legacy/v1 解析和固定 Node 接线同步回主目录。显式配置的用户路径保留；缺省路径分别解析到各自引擎。运行时轮换继续清理不兼容的会话绑定，避免把一个引擎的 journal 交给另一个。

## 复核证据

- 新增回归在未修复代码中三项失败：contained cwd 被拒、host 选项不能解析、shell 仍要求受限账户环境。修复后通过，断言读取实际写入文件的精确内容。
- CLI 完整 verify：11 步通过，4,209 个 hermetic 测试名称、38 项协议合同测试。
- Desktop 专项：181 项通过，覆盖档位、审批、固定 Node、路径解析、会话轮换及设置持久化。
- `trylo-v1-live-process.test.ts`：真实 CLI + 本机合成 SSE + 真实 shell；ask/workspace_write 在批准前无写入、批准后精确落盘，unrestricted 完成写入，read_only 无写入；已有拒绝、取消及过期操作回归保留。
- `trylo-v1-mcp-permission.test.ts`：真实 CLI 和 MCP 子进程，四项通过；批准和完全自动才产生精确文件内容，拒绝及只读无副作用。
- 托管工具分类矩阵 209 项、运行时身份与健康探针 19 项通过。
- 裁剪后旧 CLI + 固定 Node：`desktop/scripts/verify-legacy-runtime.mjs` 以合成 Anthropic SSE 驱动真实工具。一次批准才落盘、拒绝无文件、只读 Read/Glob/Grep 均返回实际结果，五项通过，无系统 Node。终态帧排空后关闭输入；首次立即 EOF 曾出现原生 libuv 退出断言，保留为退出时序负面记录，不将终态帧等同于进程干净退出。

以上属于工程和真实进程的合成服务验证，不替代真实模型质量、用户当前已运行 Desktop 的权限状态、Windows 原生输入效果、管理员窗口控制或 Android 设备验收。

## 发行与回滚

生产构建显式默认 legacy-stream-json，设置可选 trylo-v1。两套运行时与固定 Node 同包；CoWork 不进入 core。旧 CLI 源码不上传，兼容运行时通过显式制品目录暂存，逐文件校验库存哈希；声明、source map、测试示例可剔除，许可证声明保留。源码发行需要构建者另行提供该兼容制品。

可读性自审：权限决定仍由原有服务持有；执行资源只有一个所有者，没有权限故障自动回退、学习授权或新的第三方依赖。回滚可恢复前一个发行版本；独立新 CLI 不传 host 选项即可使用原有沙箱执行边界。
