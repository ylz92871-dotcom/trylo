## 发现并修复的 Trylo 问题

### 原生续接在第 33 个响应开始丢失

缓存原有 1MB 原生字符上限之外还固定 32 响应，连 absent 标记也占数量，正常小响应会淘汰仍在上下文中的思考。真实两段分别 115 检查点/298754 字符、55 检查点/168523 字符，均远未到字符预算。离线对同一实际检查点回放，旧版分别仅返回 13/54、23/37 原生内容，丢失 41、14 条；新版 54/54、37/37 全等、零错配，警告消失。

现保留 1MB 字符上限，改用 4MB 序列化 UTF8+身份 key+每条固定 256 字节管理预算，覆盖没有 reasoning 的大身份/参数。单条超限拒绝时不先摧毁旧历史；canonical 重绑定也检查体量。按 key 一次建索引，避免长会话匹配逐组扫描整个缓存。重复身份仍要求完整有序组，歧义不猜测；持久化 v2、端点/模型/作用域绑定和权限架构不变。体量会计不宣称等于 JS 实际堆占用。

8 项新回归在未修复随附制品 7 红 1 绿，修后全绿；原淘汰测试改用真实字符超限仍保留原歧义/分类断言。定向原生组 33/33。真实修复后请求另核对 3830 次回传、116 个不同身份，哈希全部与接收的私有检查点相等；无已知唯一身份缺失或错配。该证据证明续接完整性，不据此宣称所有长思考根因或确定的延迟改善。

### Desktop 随附后台终态模块仍是旧字节

真实 CPU 轮询非空时只返回进度，空终态也省略退出码。当前源码已有状态/退出码/信号/失败事实的修复，但随附制品未同步。6 项对实际随附模块的运行/非零退出/空成功退出/信号/失联/失败回归全部红；同步当前经完整门禁编译的 process-session-tools 与 presentation 后，6/6 通过，恢复后的真实后台轮询也保留终态。

## 保留的负例和实验纠错

- 一次真实 mid_stream 传输中断，在已见 tool_calls 后结束 unknown/75，候选补丁未获准或执行；恢复预检 HTTP200 后由模型核对文件继续。缺少当时底层错误码，原因未能归属，不宣称网络问题已修复，也不把它归为缓存淘汰的因果结果。后续观测器增加错误分类，并使自身日志 IO 失败不打断业务流。
- 首个宿主 oracle 对 CLI 报告额外元数据、diff 版本和未指定的增量 schedule 选择过于严格。原红例保留，修正为精确比较规定字段、完全重算允许的调度策略；不宣称 affected-only CLI 策略已验收。
- 宿主边界脚本曾误把自有临时目录写到快照；只将该目录移到快照外，业务文件未变，并在独立副本重跑，留下修正记录。
- 基础交付的空数据非法 where 被宿主发现，模型自行修复，91/91。最终独立复跑再抓到 256/257：模型改基线过滤后仍沿用旧绿色计数，测试硬编码34而实际交付范围29。本轮保留失败并让同会话修正语义范围校验、最终改动后全量重跑，未重跑已正确的 CPU 或重新生成数据。补修后模型在火山 HTTP429/rate_limit 结束，未完成自己的最终全量重跑或完成报告；宿主在隔离副本补跑全部测试、物理产物和128MB命令并通过。最终模型终态仍保留 failed，不能称为无人干预完成。此为合成任务代码/验证遗漏与提供商限流，不能算 Trylo CLI 缺陷；也证明 completed 与模型自述不构成通过。
