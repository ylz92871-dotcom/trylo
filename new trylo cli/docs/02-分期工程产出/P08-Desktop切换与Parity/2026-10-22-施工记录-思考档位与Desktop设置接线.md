## 行为合同

在设置的“模型连接 → 主模型连接”新增“思考强度”。选择随主连接、已保存模型配置一起持久化，恢复旧配置时清除不属于它的档位。选择从下一次新版 CLI 请求开始使用，运行中的请求继续使用原快照。

- “跟随服务商（默认）”表示不发送覆盖参数，不表示低档或自动低档。旧设置、旧配置未包含该字段时行为保持原样。
- GLM 5.3 / Flash 直接模型名提供 low/high/max；GLM 5.2 提供 high/max。明确识别的 GPT-6 模型按已核对的接口支持范围提供选项。
- 自定义模型及 ark-code-latest 等别名不猜测真实后端，显示支持范围未确认的说明。服务端实际采用的计算量不能从发送字段反推。
- 修改模型后，如果已选档位不再适用于已知模型，保留选择并要求重选，不静默改成 max 或默认。
- 传统 CLI 下该设置禁用并说明适用范围，保存值保留，传统 CLI 启动行为不变。
- Chat 发送 reasoning_effort；Responses 发送 reasoning.effort。公开推理摘要 reasoning.summary 与计算强度分别设置，可以同时存在。
- 终端允许 none/minimal/low/medium/high/xhigh/max，未指定时没有默认覆盖；具体模型是否接受某个值仍由其接口合同决定。fixture 等不支持的 provider 继续显式拒绝。

这次没有修改用户的全局 provider、账户、模型、密钥或当前默认思考档位，也没有进行真实付费模型性能对照。

| 边界 | 实现 |

接口依据：[OpenAI reasoning 指南](https://developers.openai.com/api/docs/guides/reasoning)、[GLM 5.3 官方说明](https://docs.z.ai/guides/llm/glm-5.3#feature-changes)、[GLM 官方仓库说明](https://github.com/zai-org/GLM-5/blob/main/README.md#note)。接口支持可能随模型变化，未知型号不套用已知型号的结论。

期间另有子智能体与 Shell 改动进入同一源码目录。初次整合快照中的旧 fixture 与新协议不一致，已保留旧 fixture 副本并同步实际 fixture。并行 Shell 修复保持原样，不计为本次档位功能。

## 兼容、风险与回滚

设置存储增加可选字段，不增加第二个设置 owner 或 credential ledger；旧数据可读。旧版本读到新字段可能忽略它；新版本读到缺失/无效字段时使用原先的服务商默认。已运行中的请求不被设置变动修改。

命名模型的档位支持表是本次核对的范围，不是自动发现任意 endpoint 能力。自定义/别名用户需按服务商说明选择；客户端不能验证服务端是否静默覆盖请求档位。此版本未声称缩短某个真实模型的思考时间。

回滚按本次接线文件的 hunks 撤回，保留其他改动及原始会话。开发资源中的旧 CLI 另存 staged-cli-before；不要整仓 reset 或以整文件覆盖并行修改。已发布安装包、APK 和比赛材料不在这次更新范围内。

可读性/维护性自审：模型档位规则与文案集中在小型纯模块；组件只负责展示和选择；持久化复用 connectionFields；运行时单次快照与 adapter 分别拥有转发和序列化。取消、权限与学习边界保持原合同。供应链无新增依赖。完整工程检查的最终数字与开发制品绑定在完成登记中补齐。
