## 实现

- **Desktop 原生宿主** 支持通过 `F_GETPATH` 检查远程产物的文件描述符路径。macOS 子路径从已打开的目录描述符解析，拒绝跟随链接，读取前继续校验路径和文件类型。Finder 定位使用 `open -R`。Windows 专属浏览器实现和 PowerShell 文件夹命令由对应平台编译。
- **Code / Work** 共用工具栏与工作区终端。Desktop 宿主选择 `$SHELL` 或 `/bin/zsh`。终端跟随工作目录，关闭后回收对应的 PTY（伪终端），`Shift+Escape` 使焦点回到工具栏。
- **CLI** 新增协议 v2 的 `darwin-arm64` PTY 制品。staging（资源组装）校验 SHA-256 和字节数，并设置 POSIX 执行位。发布清单、冻结候选和 Desktop 开发启动检查使用同一平台路径。命令入口通过真实文件路径识别全局符号链接。五个隔离调用点使用平台工厂，macOS 隔离能力缺失时返回类型化结果。
- **提前纳入的 M1 依赖** 首次全量测试留下后台子进程。POSIX 管道会话创建独立进程组。停止流程轮询组状态并保留持久权限错误，实际进程退出由回归测试检查。
- **纯净检出** 清除了当前仓库中不存在的七条历史目录例外。严格目录检查及反例测试通过。开发资源准备创建 Tauri 需要的资源目录，并保留已组装的资源。

## 自审与剩余验收

权限仍由现有 Desktop 和 CLI 审批链负责。批准只触发目标操作，拒绝保留工具错误并允许对话继续，取消关闭待审批操作。定向测试使用本地模拟模型和真实 CLI 进程，原生窗口内完成一轮模型对话及审批仍待验证。Code 与 Work 的终端只有一处共享接线。新制品沿用锁定 Rust 依赖，Windows 制品保留原始产物的哈希与来源记录。

全量门禁仍阻塞 M0 验收。M1 其余运行时工作、M2 预览与原生体验、M3 DMG 打包和 CI 尚待施工。回滚时按工作包撤销本轮对应源码与制品，保留原始检查日志和用户工作区状态。开发构建入口见 [从公开源码构建](../../../../docs/development/build-from-source.md)。
