## 实际问题与修复

### 1. 长流式输出导致二次增长的持久化开销

对近期四份会话只统计类型、字节量和错误类别，没有把原文或密钥复制到报告。第一份会话为 189,963,901 B，其中 stream_partial 为 185,395,793 B，占约 97.6%。另外三份同样主要由重复的完整片段快照构成。不能把这些磁盘字节直接当成模型上下文；模型请求另经 transcript 投影，reasoning 也不会普通重放给 provider。

原写入器每来一个片段就重新保存从头增长的文本；流式 reducer 每次 dispatch 还会把全部历史 envelope 重新交给写入器校验。128 段输出的反例中，同一个 envelope 被提交 133 次。

现在采用：

- 首次保存脱敏快照，后续只追加经过偏移校验的后缀；并行但未变化的 block 不重复保存。
- 先脱敏整个新快照，再计算后缀。路径或 secret 在后续片段到齐时触发替换，使用新快照重置，不把未脱敏后缀写出。
- 只有收到持久写入 ack 才更新前缀。失败不提前推进；关闭/重新出现的 block 不借用已删除的写入缓存。
- Engine 按已确认的 envelope 数量递交新增不可变事件；完整 transcript 的重送冲突检查保留，工具执行前的意图落盘、未知效果与取消补配合同保留。

同一 256 段、86,016 B 文本和一个不变并行 block：修复前 journal 为 11,213,930 B，修复后 172,588 B，减少 98.46%；独立 reader 读回内容逐字相同。这是固定夹具的存储结果，不是实际模型推理提速百分比。

### 2. 模型已结束，但 HTTP 不结束

Chat 适配器原本保留 finish 以接收尾随 usage；上游既不发 DONE 也不关闭连接时，可以永久卡在等待中。新增反例在 2 秒测试上限前始终不能完成。

收到真实 finish 后才启动 1 秒尾部等待上限。正常 DONE/EOF 仍立即结束并保留尾随 usage；到期取消唯一未决 read、释放 reader，发出 stream_finish_tail_timeout 降级提示及唯一 finish。不限制模型仍在生成内容或 reasoning 的时间，不重发已完成请求。usage 只包含实际收到的帧，不补造尾部数据。

### 3. 显式输出预算与上下文窗口相互冲突

原检查仅要求输入小于窗口，可能同时发送超过剩余窗口的 max_tokens。现在在完整 request 组装后，用同一 estimator 计算消息、工具表及 native continuation 开销，把显式的单次输出请求限制到剩余窗口内。总回合预算和实际 usage 累计仍由原 Budget 所有者管理。

没有显式输出预算时依然不发送 max_tokens，也没有重新加入默认 32 轮或 65536 累计输出上限。未知上下文窗口不猜测；这是本地估算边界，不宣称与所有模型 tokenizer 精确一致。

### 4. 权限、沙箱和命令失败不能混为一类

近期原始失败中有四次 read_file 的 ENOENT，这是文件不存在，不是权限拒绝。另一次历史 Shell 失败发生在辅助程序保护阶段，PowerShell Add-Type 报缺少特权；本轮在两个临时目录场景未复现，并成功完成实际严格隔离 Shell 的标记输出与清理，因此不宣称修复了所有环境特权故障。

原执行器把上述沙箱准备错误统统包装成 shell_spawn_failed，还可能把整段 PowerShell/C# 程序带回模型。现在使用 ShellIsolationError 保留准备、缺失、损坏、关闭和 helper 保护失败的稳定分类；helper 保护失败只携带有界 stderr，原异常仍保留为 cause。未就绪时不运行命令、不自动换 host、不改 ACL/WFP 策略来绕过拒绝；同一失败的准备结果不因模型重试而重复初始化。

## 持久化兼容性决定

会话外层 NDJSON 格式保持 v1，已有文件不重写；stream_partial 的 payload 增加 v2 编码：version、kind、blockId、offset（UTF-16 code unit）和 textDelta，附原有 name/redacted 元数据。

- 新 reader 接受既有 v1 完整快照，并逐条校验 v2 的原始前缀、偏移、元数据和 turn 身份；缺基底、错序、跨 turn 借用和未知版本报损坏，不部分恢复。
- v2 故意不包含旧 text 字段。旧 reader 的 isStreamPartial 会拒绝这种记录，不会把后缀误当完整答案。这是显式的向前读取限制：含 v2 的新会话需使用本版或更新版本；回滚旧程序应另开会话，并保留原文件，不能用旧程序重存新会话。
- 部分输出始终不进入模型 transcript，部分工具参数不构成可执行调用。Permission、Tool schema、UI stream 格式及学习授权没有被该编码改变。

## 自审、限制与回滚

可读性/可维护性：记录编解码、写入游标、准备失败各有单一所有者，新增模块职责小；未引入生产或开发依赖。架构：核心不依赖 UI，OS 细节留在 adapter，错误词汇经 port 传递。正确性与恢复：先 ack 后推进、校验错误终止、取消/未知效果保留，已有完整会话和压缩恢复回归通过。安全与许可证：授权未扩大，旧已授权模式不被学习或模型扩权，依赖闭包未改变。

已知限制：旧的大 journal 保留原件，历史恢复仍需读入已有大文件；没有证明复杂模型长任务、任意 CAD/电脑输入、APK 真机或新安装器质量。单次模型跳过工具不是本地拒权，也没有新增语义完成判官把 completed 改写成 verified。真实网络延迟不可由这组小样本归因。

回滚本轮源码提交可恢复前版行为；不删用户会话、不修改用户全局配置。含 v2 的会话按上文限制保留并由新版读取，旧版另开会话。公开副本的验证及最终提交绑定另记于本机审计收据。
