- 状态：待审

- 依赖决策：继续处理工具不可用；保留用户当前 Desktop 与任务，不操作界面、不重启、不替换现有运行制品。前端运行状态改动在隔离候选中完成，避免开发服务热更新影响工作。

## 发现与因果边界

前期工程记录明确保留了 `Tool permission request failed: Error: Stream closed`，但未确定原始 EOF 来源。本轮确认一条可以复现的连接破坏机制：

1. Rust `process_stop` 在终止前从进程表移除整个记录，丢弃 stdin writer。
2. `terminate_tree` 原来只检查 taskkill/kill 是否启动，忽略非零退出状态；其错误又被无返回值 killer 吞掉。
3. 因而拒绝终止时，CLI 可以继续存活，审批/控制 stdin 却已经关闭，且进程停止被报告成功。
4. 前端 `CodeRunController.stop` 同样先清除绑定、审批和运行归属，再调用 stop，并吞掉错误。

该机制已被隔离测试证明，不等于证明它是历史所有 Stream closed 的唯一来源。项目旧文档还记录过 argv prompt/非 stream-json 输入引起权限通道关闭，不能合并为同一原因。

## 行为合同与实现

- 原生进程停止检查终止工具退出状态，失败通过既有 `Result<(), CommandError>` 返回；没有新增 IPC 数据格式。
- `ProcessEntry` 持有 Running/Requested 停止状态；失败保留 writer、记录和重试权，成功请求去重。真实 exit reaper 仍是释放 CLI 记录的唯一所有者。
- shutdown 使用同一 request_stop；失败不清除记录、不计为成功，下一次可重试。PTY/LSP/workd 的停止实现没有重构。
- 新模块 `desktop/src-tauri/src/commands/process_termination.rs` 只负责 OS 终止与结果检查。Windows 使用系统 taskkill 的明确路径和无窗口启动。
- 前端候选先等待停止投递结果，再清除绑定/审批/终态；拒绝时保留运行归属并返回失败。并发停止合并，真实退出与停止回执竞态保持单次取消，未采用的 prewarm 也保留失败重试能力。
- 前端主源码未改动；可审查补丁为 `work/tool-permissions-20261020/controller-stop.patch`，包含 controller 与合同测试，`git apply --check` 通过。此处不将“补丁已准备”写成“前端已部署”。

## 自审、风险与交付状态

- 可读性/可维护性：PASS。停止状态由 ProcessEntry 唯一拥有；OS 命令结果与进程表归属分离，shutdown 复用相同方法。
- 架构：现有 IPC 类型不变；Permission Service、工具分类、MCP catalog、provider 与学习逻辑未改变。
- 错误/并发/恢复：失败不丢 channel，成功请求幂等；reaper 释放所有权。前端候选停止拒绝不发布 cancelled，保留后续重试。
- 安全/供应链：无权限扩大、全局 ACL 修改、第三方下载或产品依赖变更。真实终止测试只用测试自己创建的 PID。
- 未完成：当前原生 exe 和长期 CLI/工具进程没有加载新代码；前端补丁未应用。Windows Click/Type 真实效果、用户 CAD 缓存原始异常、完整 CAD 绘图/标注工作流和安装制品仍未验收，整体工具问题不标记解决。
- 已知余项：控制器的其他生命周期路径仍有旧 catch/清理逻辑，不能把此次 stop() 候选验证扩大成全部进程生命周期已经收口。
- 回滚：只撤回本轮 native 文件增量；原件位于证据目录的 `.before`。前端未应用，无需回滚活动 App。不得清理用户进程或覆盖此前未提交的工具/远控/界面工作。
