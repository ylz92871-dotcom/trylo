## 三处缺陷与失败证据

| 缺陷 | 未修复结果 | 修复行为 |
| --- | --- | --- |
| 整轮结束才计费，单轮多次请求越过预算后继续执行 | 真实火山链式读取任务：第 4 次响应累计已超过 4000，第 5—9 次请求仍发出；整轮结束才以 28125 tokens 报 token_budget_exhausted。委派与交互两类 worker 的回归均观察到 8 次请求而非应有的 3 次 | 共享 child-provider 包装器按每次 provider 响应收费；消费 finish/error/cancel_ack 前提交已观察到的用量，断流/中断清理路径补记尚未收费部分；下次请求前即受治理信号约束 |
| 长轮次取消时遗漏此前已完成请求的用量 | 两类 worker 在第一请求完成、第二请求阻塞时取消，终态 usage 仍为 0/0；期望 80/20 | 用量在各响应结束时已进入唯一治理 owner；取消终态保留先前请求的已知用量，不再等待 runTurn 整轮返回 |
| 取消后立即 resume 可能读取清理前的旧检查点 | 旧 worker 已返回 cancelled，但 provider 尚在清理、最新 transcript 尚未交付时，resume_agent 直接启动新实例 | runtime 继续区分终态与 worker 实际退出；resume_agent 对尚占活动记录的终态返回 agent_stopping，清理后再允许恢复，并以测试确认取消前工具结果被继承 |

red-budget.tap 包含四条修复前失败断言；red-resume.tap 为恢复竞态的确定性失败。修复使用既有 runTurn 与 runtime，未复制执行引擎，未放宽权限或提高默认治理上限。

## 真实长任务结果

1. 临时密钥预检 HTTP 200，ark-code-latest 本次预检实际返回 deepseek-v4-1-flash。
2. 默认预算链式读取：每个 node-N.json 才给出下一文件名，迫使模型逐次消费真实 read_file 结果。修复前 9 次请求、28125 tokens；修复后 4 次请求、6322 tokens，第一次观察到超限后新增请求数从 5 降为 0，两次都保留为明确 failed，未把预算终止宣称任务完成。
3. 默认超时边界：真实模型先返回 IDLE_READY，等待 62 秒后为 timed_out，活动实例归零。这是现有总生命周期超时的实际效果，不列为修复成功的长任务完成。
4. 显式扩展预算长跑：3 个并行子任务，各完成初始响应加 8 次追问，共 27 次真实 provider 响应、每子任务 9 轮。各自的 anchor 和 counter 逐轮断言，最大并发 3。基线 73168ms、候选 73578ms，均完成全部轮次、关闭后活动实例为 0。每轮追问之间明确插入 8 秒等待，属于有间隔的多轮真实会话测试，不是连续计算 74 秒的宣称。
5. 真实链式任务在第二请求开始后取消：终态保留第一请求的 620 input / 49 output tokens；等待 worker 清理后恢复，随后按序读完 8 个节点并返回全部 code。全程恰有 8 次 read_file，没有重复读取第一节点，清理后活动实例为 0；结果见同目录 evidence/2026-10-23-subagent-long-task/fixed-cancel-resume.json。

4000 不是此补丁承诺的精确消费硬上限。供应商通常在响应结束才返回 usage，因此触发判停的这一次请求仍可能使总量超额；本补丁保证已观察到超限后不继续发后续请求。未观察到的供应商用量、请求中的部分生成和订阅服务限制不能从本地日志推定。

- 可读性/维护性：两类 worker 复用一个小型 provider 包装器；治理 tracker 仍是总用量与停止策略唯一 owner，复用 mergeUsage 处理每个响应内的 snapshot/delta，移除原轮尾的重复计费。
- 生命周期：recorded 在计费调用前置位，避免超预算抛错后 finally 再计一次。断流仍计已知 usage；取消与 timeout 仍由 runtime 决定终态及资源释放。
- 兼容：现有工具参数、输出字段和持久化格式不变；新增可重试错误 agent_stopping，含义是取消已被接受但旧 worker 尚未完成清理，不能从旧检查点安全恢复。等待清理完成后重试 resume_agent。普通已退出终态的恢复不变。
- 权限与架构：未扩展子任务工具权限、独立审批或默认预算；核心不依赖 Desktop/UI 类型。
- 供应链：不新增、升级或替换依赖；许可证与 SBOM 由最终 verify 检查。
- 审计边界：本轮是作者自审与实际进程/provider 验证，不冒称独立第三方审计；没有重新验收原生 Desktop、安装包、设备或所有供应商。
