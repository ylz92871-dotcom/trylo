## 新发现与修复

### 1. 满并发时预期拒绝被作为异常抛出

四个子任务已占用槽位后，spawn_agent、resume_agent、delegate_subagent 三个入口都抛 SubagentGovernanceError。控制端无法按 ToolOutcome 的稳定 code 处理正常容量不足。三个合同断言在未修复代码上均红；真实火山基线也记录到第五次派发直接抛错。

修复将预期的治理异常统一转换为 error outcome，保留 concurrency_limit_exceeded 与原因。转换函数只有一个；不属于治理拒绝的异常继续抛出，不吞掉程序缺陷。拒绝不建立第五个 worker、不调用 provider、不扰动原四个任务；实际退出并释放槽位后可再次派发。

### 2. 子任务失败原因被压成通用 failed

鉴权、限流、参数和网络错误，在委派与交互两类 worker 中都变成 code=failed、message=Child attempt failed with terminal reason: failed。八条诊断断言在基线上均红；真实不存在模型请求的 HTTP 404 也只得到该通用错误。

修复复用执行循环已归一化的 inputs，保留最近的 transport/budget/tool 失败原因及其稳定分类；两类 worker 共用 requireCompletedChild，无第二份诊断策略。已有成功终态不受历史失败影响。只传递循环已有的脱敏诊断，不读取原始请求头、凭据或 reasoning。

## 确定性压力结果

- 1000 个固定种子，每种子 200 步信箱操作，共 200000 步，与独立队列参考模型逐步比对。
- 接受 104051 次投递、拒绝 12008 次投递、15919 次等待中读取消；逐步检查队列顺序、interrupt 替换、关闭语义、轮次计数及 AbortSignal 监听器清理。
- 64 个生命周期批次，每批四路子任务、每任务 12 次追问；共 3072 次追问，逐个核对独立输出与有界历史。
- 单一阻塞子任务上重复取消 1000 个 wait 观察者，断言不取消任务、不遗留观察计时器和监听器。
- 200 次执行超时与强制关闭交错：100 次 timed_out、100 次 cancelled，各只产生一个终态，worker 退出后槽位和计时器均归零。
- 整组创建 457 个合成子任务，3529 次合成 provider 请求；最终活动实例和剩余计时器均为 0。

以上是脚本 provider 与可控调度器证据，不能算成真实模型调用数量或普遍模型可靠性。

## 真实火山压力场景

预检 HTTP 200，ark-code-latest 本次预检返回 deepseek-v4-1-flash。基线诊断场景完成四路实际调用，捕获并发拒绝抛错和不存在模型诊断丢失。

候选真实长跑设计为四个固定 anchor、不同初始 counter 的子任务，初始响应后再进行 32 轮加减乘操作，逐轮逐子任务核对 anchor 和算术结果。每轮间隔 4 秒，属于持续多轮会话，不宣称同一请求持续计算整个墙钟时长。

第 8 轮后，对一个等待中的子任务在同一 JavaScript 任务中灌入 100 条追问：要求准确接受 33 条（1 条已交付、32 条排队），另 67 条以 agent_input_queue_full 拒绝；随后 interrupt 替换尚未消费的队列。立即观察不应暴露旧答案，最终必须恢复原 anchor 与有效算术 counter，不能让 noise 回复满足新要求。

长跑结束后关闭四个实例，再请求不存在的模型，父任务实际收到 invalid_request 与 http_404 诊断。全场断言通过：耗时 202423ms，四路 32 轮追问全部完成；135 次真实请求中 134 次 HTTP 200、1 次预期 HTTP 404。总已观察用量 115334 tokens，最大并发 4。100 条灌入准确接受 33、拒绝 67，替换后恢复为 AN_0_6712:64；第 32 轮四个 counter 分别为 4600、30200、55800、81400。清理后活动实例为 0，完整摘要见 verification-summary.json。
