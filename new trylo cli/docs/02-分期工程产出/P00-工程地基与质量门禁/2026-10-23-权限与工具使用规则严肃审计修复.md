明确优先级：沙箱及显式拒绝不能被自动策略放行覆盖；会话记忆拒绝先于策略；显式命令 forbidden 先于普通 permission approve。配置策略的未知 shell 语法拒绝，匹配 prompt 的命令继续原权限链。策略允许是操作者对具体命令的明确允许。

## 接线与兼容决定

- **实际默认行为**：未提供 execPolicy 的 host 与旧调用兼容；本轮未新增策略文件 CLI flag、未自动读取全局策略，也未宣称默认启动会装载前缀规则。已修复的是可注入的端到端接线与策略自身的完整命令检查。
- **已有授权语义**：`--allow-tools write_file` 等显式整工具授权仍有原含义，不能误标成仅工作区授权；沙箱依然可以拒绝它。隐式自动编辑现在严格限于工作区，过去依赖隐式授权写外部文件的行为会被拒绝。
- **内存合同**：PermissionChoice/PermissionPlan 增加可选 `workspaceEdits: "auto"`；没有持久化格式迁移或新的协议事件。StdioApprovalOptions 增加可选 scheduleExpiry 注入缝，生产默认仍为十分钟。
- **边界失败**：新增/收紧 `permission_action_fingerprint_mismatch`、`permission_ticket_tool_mismatch`、`invalid_permission_decision` 与 `exec_policy_unverifiable`；前三项通过既有 request/decision failure 合同返回，不制造审批成功。
- **既有测试夹具修正**：wrong-ticket 测试改为有效 fingerprint，继续验证原 ticket-mismatch；auto-edit 测试给 write_file 实际 path/content，继续验证原批准/询问行为，另补外部路径拒绝回归。未删除断言或降低门禁。
- **架构**：核心只依赖 PermissionPort、ExecPolicyGuard 等端口；具体路径解析、shell 策略构造与 UI 展示留在外围。Permission Service 是授权所有者，学习模块没有新增授权能力。

## 按顺序自审

1. **可读性**：会话、授权、准入、路径与展示各有清晰入口；完整命令展示复用一个 builder。host 的纯状态判定移至已有状态模块，避免超长文件。
2. **可维护性**：决议 guard 与 fingerprint 算法各有单一权威；工作区路径复用真实执行端 resolver，patch 复用 parser。没有为测试制造第二套权限策略。
3. **架构**：可选 host 注入贯穿既有端口，不向核心引入 shell/文件适配器或 Desktop 事件依赖。
4. **正确性**：覆盖允许、拒绝、过期、无输入、错误 ticket、旧回复、参数被改、外部目标、多步骤 shell 和真实 spawn 副作用；完整门禁最终结果另列。
5. **安全与权限**：工具输出/学习提案没有新增授权入口。隐式授权不可变成整工具授权，策略不可分析时拒绝；显式操作者允许仍依其明确语义执行。
6. **依赖与供应链**：没有引入或升级依赖；锁文件未由本轮修改，许可证与静态供应链检查属于完整 verify。
7. **证据**：保留 RED、首轮完整失败、脚本、源码哈希、真实进程 marker 断言与浏览器交互检查；不以 completed、自报或截图替代执行证据。

## 已知边界、风险与回滚

- 前缀执行策略不分析任意解释器脚本内部的全部副作用，也不构成 OS 级隔离。未配置 guard 时不额外产生此前不存在的命令策略。
- shell 的实际行为仍取决于操作者明确授权的解释器、工具和脚本；本轮没有承诺所有 MCP、网络或外部工具普遍安全。
- 审批超时无法取消底层 stdin 读取；实现保留单个 pending reader，让后续请求继续使用，避免竞争读取。程序生命周期仍由原宿主管理。
- 本轮验证为源码、隔离 CLI、本地 HTTP/进程和 headless UI。运行中的 Desktop/Service Host、新安装包、真实供应商和设备尚未在本轮替换或验收。
- 回滚以 `source-binding.json` 的路径和相应审计差异为范围，参考冻结 V3 与 `initial-source-drift/`；不要整文件恢复含并行改动的 host/wiring/provider 文件，更不要 reset 工作区。回退 deny_all、fingerprint 或目标约束会重新引入已复现问题。
