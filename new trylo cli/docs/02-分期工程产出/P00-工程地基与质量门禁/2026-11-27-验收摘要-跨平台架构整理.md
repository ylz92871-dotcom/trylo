## 交付边界

正式结构及依赖见[当前架构](../../../../docs/architecture/README.md)，91 项移动见[迁移表](../../../../docs/architecture/platform-migration.json)。外部 IPC、CLI 命令、执行与权限状态合同保持兼容。公共调用者改走平台选择入口；Windows 保留现有实现，Mac/Linux 未接通的隔离与资源准备报告不可用或待接入。电脑控制不可用不阻断其余会话，用户关闭电脑控制仍有效。

Windows stdin 辅助进程的源码读取与受保护缓存同步采用 sandbox/windows 层级，缓存身份绑定布局、文件名和内容。预览重建配方的路径与配方摘要同步更新，发行二进制、上游源码和工具链版本固定值保持不变。Git 明确跟踪 build 脚本源码，预览配方与生成工具清单使用固定 LF。

公库的目录待迁清单移除七条仅描述私有本地工作状态、且在干净公库中不存在的记录。没有删除原本地目录或用户状态；目录检查逻辑没有放宽。历史验收正文、源码快照与旧摘要保持原样。

## 复现入口

仓库根目录：

    node scripts/check-workspace-layout.mjs --strict
    node scripts/release/check-source-completeness.mjs
    node --test desktop-services/tests/services/platform-profile.test.mjs desktop/scripts/build-platform.test.mjs desktop/scripts/stage-cli-options.test.mjs
    python -B -m unittest desktop/scripts/test_package_portable.py

desktop 中执行 pnpm build。原生测试先准备前端产物及 Windows prepare.ps1 固定版本的 Node，再在 desktop/src-tauri 中执行 cargo test --offline --locked --lib -- --test-threads=1。desktop 中的预览相关 Vitest 使用 --pool=forks --maxWorkers=1 --minWorkers=1。

new trylo cli 中执行 node scripts/quality/verify.mjs。该入口会编译并运行其原有合同、hermetic 和后续检查。本次第 6 步发现全量范围为 1471 个测试文件后，停止本轮启动的检查进程树并保留日志，转为受影响回归；第 7–10 步另用同一检查函数执行通过。没有改动检查器，也未调用付费模型。其完整结果及受影响测试命令由本机证据目录中的 run-acceptance.cjs 保留。Services 回归的精确文件列表和命令由同目录 run-final-checks.cjs 保留。这些本机证据位于被忽略的工作目录，公库不包含原始日志。

平台选择测试曾对照原版执行：原版 3 项通过、5 项失败，失败原因为 Mac/Linux/未知系统仍选 Windows 包；整理后 8 项全部通过。

## 失败、修复和未验证项

CLI 全量质量入口未完成，不能标记为全部通过。第 6 步保留已开始运行的原始记录，未把未完成的全量回归计入通过项；实际交付依据为受影响的 41 项 CLI 回归、38 项合同、严格编译、平台选择测试及各工程检查。

CLI 第 4 步的八条诊断涉及 permission-refusal-detail.test.ts、running-shell-cancellation.platform.test.ts 和 running-tool-cancellation.test.ts；三个文件本轮均未修改。使用原 main 456e450 中的相同检查函数、loop/domain/ports 源码与负例 fixture 在独立目录复现完全相同的八条诊断。保留原检查，没有删除测试或改动断言。

初轮发现的迁移路径错误、Office 测试夹具父目录、stdin 辅助模块与缓存层级、Git 忽略 build 源码、生成目录 CRLF 及配方摘要问题均已修正，并由对应检查验证。Rust 初轮缺少前端与随包 Node，按固定输入补齐后 181 项通过。Vitest 默认线程池在测试结束时报 V8 Empty MaybeLocal；forks 单 worker 下相同断言通过，原失败日志保留。

Rust ignored 中包含显式子进程 fixture、符号链接权限条件，以及依赖真实媒体和 Office 引擎的验收；Services 跳过四项嵌入 Python 图像探测，Vitest 跳过三项媒体引擎验收。Office 字节篡改负例缺少随包 LibreOffice manifest，未完成。没有把跳过或缺少输入算为通过。

本轮未合入完整 Mac/Linux 适配，未验收 macOS 14 真机、Linux 原生启动/发行依赖、Wayland 电脑控制，也未重新打包或发布 Windows 安装包。后续分别按平台接入指南处理。

## 扩展黑盒复核与实际闭包

第 6 步首批观察到九条 CLI 进程测试失败后，单独串行复核 compact-model-summary、context-evidence、desktop-stdio、goal-stdio 四个原测试文件，当前首轮为 2 通过、8 失败。另从原 main 456e450 导出完整 CLI 源码，用同一 TypeScript 的 --noCheck 发射原始源码、复用同版本依赖和未改动的 vendor 运行输入，运行相同测试，原版为 4 通过、6 失败。这是运行时基线对照，不是原版严格构建通过声明。

两项压缩测试在两边均缺少 compact 记录。资料来源测试在原版单独复核时也出现完全相同的 lost read source 断言。桌面拒绝与 EOF 取消测试在两边均被原有 10 秒定时器终止，退出码为 null。当前目标组首次三项失败，专门隔离复核为 1 通过、2 失败；临时诊断副本仅把外部 kill 等待窗口改为已有 staging 使用的 180 秒，保留全部行为断言，三项通过。随后对未修改的原测试按原 20 秒窗口最终重跑，三项全部通过（系统暂停约 11.2 秒，暂停加恢复合计约 29.4 秒，取消约 14.6 秒）。原测试文件、等待时间和断言均未修改，所有尝试保留，不把整组黑盒测试写为全部通过。

最后通过移动后的 shared/stage-cli.mjs 对当前冻结 dist 执行 --skip-build --prepared-closure，在 D 盘仓库外复制 CLI 与固定 Node。沿用原脚本 180 秒预算，依赖解析、审批前不得写入、收到允许后实际写入及唯一 run_result 均通过，实际约 101.9 秒。固定 Node 摘要与 Windows prepare 输入一致。它证明本次资源路径迁移后的 CLI 闭包可独立工作，不替代完整安装包验收，也不将进程测试失败全部归因于启动速度。

本机原始证据还包括 cli-observed-integration.log、baseline-cli-integration.log、baseline-context-isolated.log、cli-goal-isolated.log、goal-startup-diagnostic.log、cli-goal-original-final.log 及 cli-staged-smoke.log。只有实际通过的原测试计入上表；180 秒诊断不是对原失败结果的替代。
