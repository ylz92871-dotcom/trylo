## 已确认的缺陷与本轮修复

1. Windows PowerShell 5.1 的原生进程 stdin 默认编码会丢失中文。新 CLI `shellExecArgv` 和旧 CLI PowerShell provider 显式配置无 BOM UTF-8 的 InputEncoding、OutputEncoding 和 `$OutputEncoding`。旧 provider 的直接启动与 POSIX 沙箱包装使用同一转换函数。这里修的是 PowerShell here-string/多行脚本与原生 stdin，不把 Bash heredoc 语法改解释为 PowerShell。
2. 新 CLI 将 PowerShell/Bash 也标记为需要 Windows verbatim 参数的命令；实际 spawner 因此丢掉正文中的双引号。现仅 cmd 使用该模式，其余解释器由 Node 保持完整参数边界。批准对象、工具参数、工具 catalog 和调用权限未扩张。
3. Desktop 最终权限策略对托管工具的 `prompt` 分支可能在只读模式继续提供执行审批。现只读模式仅接受已分类的读操作，其他托管副作用直接拒绝。新旧 CLI 共享该最终策略；工具包明确拒绝在所有模式仍优先。
4. CAD 1.5.1 适配器此前仍使用会读取共享 makepy/gen_py 缓存的 pywin32 wrappers。候选修补改为动态分派，在已运行实例上先取得原生 IDispatch 再包装；仅未运行时按原有逻辑启动。模拟生成缓存损坏时，原版失败，候选能 attach/launch。不删除或重建共享缓存，不修改现有安装目录。

## 真实现场边界

- 只读检查发现实际运行的 Trylo Desktop、Service Host、相关 CAD/Windows 工具进程为 High（RID 12288）。Codex 受限执行环境启动的诊断子进程为 Low（RID 4096）；这不能代表用户 Desktop 的权限。
- 当前 Desktop 实际使用 legacy CLI，存在多个长期保留的会话进程。本轮没有结束任何进程。
- Windows-MCP 的 core、desktop service、入口、临时目录及 comtypes cache 文件在仓库与当前受管安装中内容相同。尚未证明点击失败的现场触发条件。
- 用户提供的是 CAD 连续建圆、批量建图及尺寸标注记录，没有具体缓存异常原文。不能据此断言 gen_py 是该历史故障的确定根因。
- 界面读取返回 `Computer Use was not approved to use trylo-desktop`，未取得截图或执行点击。后续用户明确需要继续工作，未再请求 UI 操作。

- 可读性、可维护性：PASS。shell 参数机械处理复用已有 needsVerbatimArguments；旧 provider 编码只有一处转换；最终权限仍由既有 host policy 所有。
- 架构与权限：未向 loop 添加 UI 逻辑；未修改授权所有者、沙箱准入或增加允许项。只读收紧属于符合既有产品说明的缺陷修正。

- 生效边界：本轮未重建/替换旧 CLI `cli.js`、未替换受管工具目录、未重启当前 CLI/工具进程。当前长驻进程不能视为已加载本轮源码修复。
