# 2026-10-23 工具使用者视角对抗审计与修复

## 任务和证据边界

本轮按用户“作为工具使用者来审计修复”的要求，把检查入口换成任务流程：按工具实际说明调用，观察真实文件、子进程输入输出、失败后的恢复信息，以及模型实际收到的工具文本。继续应用仓库 `$trylo-code-quality`，不增加依赖、不替换运行中的 CLI/Service Host、不修改供应商配置、不发起 Git 提交。

生产入口是 `createWorkspaceTools`。新增 `tool-user-journeys.test.ts` 中的流程使用该目录直接执行真实工具；这是工具消费与执行证据，不是经过真实模型决策或人工审批 UI 的端到端验收。`failed`/`lost` 的不可控终态通过明确的端口故障注入验证，其余相关进程、stdin、文件与 marker 检查使用本地真实子进程。测试工作区均隔离并清理自己创建的进程和文件。

证据：[2026-10-23-tool-user-audit](./evidence/2026-10-23-tool-user-audit/)。最终完整门禁 **11/11 通过**，本轮源码与冻结候选、当前整个 CLI TS 源码均无哈希漂移；准确结果见末节。

## 使用者应能依赖的合同

1. 工具说明中允许省略的参数，实际省略时应能工作；非法显式参数应指出字段和正确类型，不能静默变成另一个操作。
2. 成功读取进程状态，不代表被观察的命令成功。工具文本和结构化值都必须包含实际终态、观察到的退出码或失败/失联原因，不能要求模型从日志措辞猜测。
3. 多步骤命令后续失败，已经完成的步骤、输出和副作用仍是事实，不能在错误分支消失，也不能诱导盲目重跑整个流程。
4. 读取上限、传输分包和缓冲淘汰不能把合法中文、emoji 变成伪造字符。真正不完整的最终 UTF-8 才显示替换字符；零读取预算不消耗数据。
5. 本轮不扩大权限。已有拒绝、取消、沙箱、会话归属与输出上限继续有效。

## 复现与修复的五类问题

| 问题 | 使用者会遇到什么 | 修复 |
| --- | --- | --- |
| 可选 yield 实际必填 | `run_shell` 提示用 `write_stdin(sessionId=...)` 继续，但照着调用得到 invalid_arguments；发送 chars 时也一样 | 缺省 input yield 使用 250 ms，缺省 poll 使用 1000 ms；显式非法值仍拒绝，合法短 poll 保留原来的 anti-spin 下限。描述补充缺省语义，不更改参数 schema。 |
| 观察结果丢失终态事实 | 非零退出的后台测试只返回日志；`list_processes` 文本、已结束后的 stop、再次写入的错误均丢失实际退出码；failed/lost 只剩种类或最后几行输出 | 通过 `process-session-presentation.ts` 共享终态字段与措辞；poll 文本始终先给状态，再给日志。exitCode、signal、failureCode/failureMessage、lostReason 按实际分支返回，失联不捏造退出码。stop 保留观察到的旧终态，不冒充命令成功。 |
| 错误参数被静默忽略 | `chars:123` 变成轮询；`eof:"true"` 不会关闭输入；`runningOnly:"true"` 得到未按预期过滤的列表 | 在读写和列举发生前，统一验证可选字符串/布尔参数；返回现有 invalid_arguments 合同，字段名与所需类型可见；真实进程未收到错误输入且仍可继续使用。 |
| 后续启动失败抹去前面执行事实 | 第一条命令已经产出文件和日志，第二条 ENOENT，返回信息却只说缺少程序，前面的输出丢失 | shell 启动异常分支保留累计 stdout/stderr 与截断信息，报告此前已完成步骤数、后续未运行，并提示检查先前副作用后再重试。真实 marker 证明第一步执行、最后一步没有执行。 |
| 后台中文输出损坏 | 一个字符被切成两个传输包、stdout/stderr 交错、轮询字节上限或淘汰边界，都会产生本不存在的 � | 使用 Node StringDecoder 的共享 UTF-8 sink；普通管道每个输出通道独立携带半个字符，持久化镜像仍保留原始字节。缓冲读与淘汰按字符边界执行，真正的传输结束才 flush 不完整尾部；PTY 终态调用相同 buffer end，两个 registry 的读取上限最低为四字节。 |

没有把多个断言冒领为多个独立缺陷。新增使用者流程共 17 条，其中两条是对照：多语言含空格路径的发现→读取→CRLF 编辑→真实 stdout 文件，以及显式非法 yield 在发送输入前拒绝。

## 结构、兼容和失败合同

- 本轮仅触碰 `source-binding.json` 中列出的 11 个 CLI 路径。候选为 `D:/CC/trylo/work/tool-user-audit-20261023/candidate`，包含冻结时已有的其他并行源码改动；本轮不认领那些差异。
- 工具参数 schema 未变，没有由本轮引发的 catalog schema 哈希迁移。描述可以按原机制更新，旧会话沿既有兼容路径运行。
- `write_stdin.value.output` 继续是纯新增进程输出；顶层模型文本新增状态前缀。既有 `status` 和字符串 `end` 保留，终态细节与 bufferedBytes 是可选、增量字段。读取成功依然返回 result，命令本身是否成功由 exitCode/signal 决定。
- `invalid_arguments`、`session_finished`、`shell_spawn_failed` 等现有错误码不变，恢复信息更完整；不会把参数错误自动纠正为另一个有副作用的调用。
- `BoundedBuffer.end()` 是适配器内部的新增终结入口；正常管道在 stdout/stderr 实际关闭时结束解码，PTY 在终态结束解码。buffer reset 丢弃旧 carry 并重开空解码器。读取预算小于一个字符时保留该字符，生产 registry 将过小配置提升到四字节，避免无法推进。
- stdout 与 stderr 的原始字节仍按原 publication 路径持久化；字符解码属于用户观察面，不修改进程命令、权限或持久化状态格式。
- 将管道解码与流关闭的机械职责提到 `session-output.ts`，会话 registry 保留生命周期所有权，避免超过文件行数预算；未提高门禁限制或以删空行规避。

## 按规定顺序的自审

1. **可读性**：参数检查先于副作用；终态文案与字段由一个模块生成；流关闭和解码在独立小模块，不混进权限或业务循环。
2. **可维护性**：使用 Node 的流式 UTF-8 decoder，没有重写字符解码器；字节截断边界共用一个 continuation 判定；stdout/stderr 各自有 carry，共用同一机械接线函数。
3. **架构**：变更局限于外围工具/进程适配器；Execution Loop、学习控制面、Permission Service 的授权责任未扩张，没有新增核心对适配器或 Desktop 的依赖。
4. **正确性**：真实输入、真实非零退出、先前 marker 与后续未执行 marker、连续 poll 的字符逐字比对提供外部可见证据。不可控失联有明确故障注入标识，非“真实设备断联”声称。
5. **权限和安全**：非法字段在发送前拒绝；没有增加对未知 session/PID 的操作能力，没有扩大允许列表或取消沙箱；失败信息明确先前步骤可能已有副作用。
6. **供应链**：只使用 Node 内置 StringDecoder，没有新增/升级依赖或锁文件。完整许可证与源码扫描由最终 verify 确认。
7. **证据**：保留首轮、修复后再次发现、错误负例校正与主动停止的日志；精确说明 native PTY 跳过，不用测试数包装真实模型、安装包或设备验收。

## 风险与回滚

- 依赖完整原始顶层工具文本的私有调用方会看到状态前缀；需使用保持原意的 value.output 读取纯进程数据，或接受新状态摘要。此变化是为了让模型可见文本不再抹去失败。
- 合法输出中的字符不被工具切坏；源程序实际输出非法或最终残缺 UTF-8 时仍会出现 �，这是解码事实，不能承诺修复源程序编码。被淘汰的输出仍显式报告 dropped/truncated，不伪造全量日志。
- 进程结束、后代树清理、原生 PTY 可用性和真实供应商运行是不同验收层；本轮没有构建或安装缺失的 PTY helper。
- 回滚以绑定的 11 个路径和本轮差异为范围，可参考上一轮候选源码，保留并行修改。新模块与调用点需成组回退，不做整树 reset，不恢复凭日志猜测成功或静默忽略非法参数的行为。
