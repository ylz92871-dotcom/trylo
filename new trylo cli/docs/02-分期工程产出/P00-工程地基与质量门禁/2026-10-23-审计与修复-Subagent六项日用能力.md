## 实现边界与兼容

物理执行的生命周期仍由 `SubagentRuntime` 管理。新增 `ControlAgentSessions` 负责逻辑会话、最新执行别名与订阅；`settlement.ts` 负责可取消的退役观察；`budget-snapshot.ts` 统一累计与展示；`fork-context.ts` 统一不可变前缀；`control-input.ts` 统一边界解析；`inherited-authority.ts` 提供只读授权与拒绝新审批的策略。没有新增依赖或第二套权限所有者。

预算必须跨停放、恢复和真正重启累计；取消后供应商清理阶段迟到的 usage 在退役时入账。等待者订阅逻辑任务，避免仍挂在旧执行上。只有完成且确实可继续的停放记录允许透明重开。

核心领域通过版本化协议传递 `taskId`、预算与输入模式，Desktop adapter 才转换为 UI 状态。`SubagentConversation`、avatar、草稿与轮次按逻辑任务合并，仍向当前物理执行发送控制。模式完整经过 UI → App → host stdio → CLI。发送失败显示错误并保留草稿。

新增协议字段为可选字段，旧调用方仍可工作；旧 `interrupt` 保留原语义。默认空闲释放是有意的行为变化，完成后的任务可在父运行仍存活时继续输入。本次没有修改持久化文件格式；逻辑会话及 fork 前缀仍属于当前父运行，不能据此声称整个进程重启后可恢复完整会话。

本次增量涉及 44 个源文件（28 CLI、16 Desktop），详见 [scope.json](evidence/2026-10-23-subagent-usability/scope.json)。既有脏工作区中的先前修复与其他模块修改未纳入本次回滚补丁。`scope.json` 区分回合开始副本、原本干净的 HEAD 基线与新文件。

## 红例、独立复核与修复

新增回归先在未修复候选运行，保留原始失败，随后修复生产实现。证据目录中的 `red-usability.tap`、`red-extended.tap`、`review-red.tap`、`authority-red.tap`、`late-grant-red.tap`、`stdio-red.tap` 与 `red-desktop.log` 覆盖六项合同、恢复计费、等待迁移、失败停放、精确授权、授权刷新、stdio 模式与 UI 状态。

独立只读复核先后确认并推动修复：取消清理阶段漏算 usage；pending wait 留在旧执行；无父授权时发起无效审批；失败任务被错误停放；生产 wiring 固定了构建时授权快照。最后一项补齐 getter 后，新增父精确授权可用于新 spawn / delegate，旧 child 仍保持原工具上限。复核实际执行了授权调用，父审批请求为 0，父授权记录未被子任务改写。最终复核无剩余可复现 P1/P2；这不代表穷尽所有缺陷。见 [独立复核记录](evidence/2026-10-23-subagent-usability/independent-review.md)。

原有两处断言随权限合同更新：未授权 child 不再打开审批，调用未执行；越权不再伪装为正常完成，而是类型化权限失败。这些断言仍检查真实副作用和失败原因。

## 自审、限制与回滚

可读性与可维护性自审通过：会话、物理生命周期、预算、fork 和授权各有单一入口，解析与策略从调度机制分离。没有把 UI 格式引入领域，也没有学习系统授权路径。独立复核按可读性、可维护性、架构、行为、权限、并发恢复、性能、许可证、文档测试顺序完成。

已知限制：token 在供应商响应上报 usage 后执行预算检查，可能超过上限一个响应；主动等待结束会暂停执行时间计费，但供应商取消清理仍须真实退役。无法响应取消的 worker 在 5 秒后仍可返回 `agent_stopping` 并保留占位。预算显示是最近上报值。图片继承已验证传输字节与结构，没有验证真实模型图像理解质量。原生 Desktop / WebView2、安装包和完整进程重启恢复不在本次已通过范围。

[incremental.patch](evidence/2026-10-23-subagent-usability/incremental.patch) 只描述本次相对回合开始基线的修改，避免把早前未提交修改算入回滚。已运行 `git apply --reverse --check --whitespace=nowarn`，退出 0，见 [rollback-check.txt](evidence/2026-10-23-subagent-usability/rollback-check.txt)；仅检查，没有实际反向应用。实际回滚前仍应按 scope 当前哈希核对并发修改。构建快照、红例和原始 provider 失败留存，不删除或覆盖。
