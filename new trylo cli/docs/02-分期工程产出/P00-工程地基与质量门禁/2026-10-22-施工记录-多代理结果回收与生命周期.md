# 多代理结果回收与生命周期修复

## 范围与行为契约

本轮处理 WP22 新 CLI 的交互式多代理控制面。问题不是缺少工具名，而是控制面不能可靠地回收子任务答案、等待取消及恢复配置。保留 `--subagent` 显式启用方式，不改变 PermissionGate、子代理工具授权边界或父会话的供应商设置。

兼容性决策：`wait_agent` 保留原有 `status` 和 `timed_out`，增加 `results[agent_id]`，含 `output`、`phase`、`round`、`status`，终局有错误时含 `error`。`phase=awaiting_input` 表示一轮已答完，运行时仍为 `running`，可以继续 `send_input`；生命周期终局由运行时唯一持有，不把一轮答完伪装成整个代理完成。

- 一次等待只使用一个总截止时间，任意目标出现可用轮次答案或终局即返回全部目标快照。默认 10 秒，上限 60 秒，零为立即快照；负值和非有限值拒绝。未知目标明确返回 `unknown_agent`。
- 取消等待只撤销该次观察，不取消子代理；结束子代理使用 `close_agent`，`force=true` 立即请求取消，普通关闭完成当前及已排队轮次。
- 新追问使此前轮次不再满足等待；返回当前轮次文本，排除继承、分叉或上一轮答案。失败不能继续假装空闲，更不能用上一轮成功答案代替失败轮次输出。
- 角色提示词、迭代上限及子模型覆盖进入真实子请求；恢复沿用原解析后的角色、模型和收窄工具范围。恢复产生新 ID，不复活原终局；超时终局可恢复。
- 输入队列上限 32，满时返回 `agent_input_queue_full`；`interrupt` 仅替换尚未开始的排队输入。读取前已取消的信号立即拒绝，不会永久挂起。
- 控制面保留最近 64 个终局代理供观察及恢复，超过后最早终局被遗忘并返回 `unknown_agent`。活动并发仍由原治理器限制。
- 父 wiring 关闭先请求取消所有子代理，再关闭共享资源。取消不等于底层 worker 已退出，不提前归还并发槽；无响应 worker 仍占用原槽位。

## 架构与失败边界

`AgentRoundObservation` 只缓存轮次报告和运行时终局供读取；单截止时间及取消订阅释放归该观察模块。执行继续复用 `runTurn`，失败判定与阻塞式子任务共用 `requireCompletedChild`。共享资源的生命周期归 CLI wiring，输入容量归输入通道。没有增加第二个执行引擎、审批通道、学习策略或依赖。

角色的迭代上限按每次 `runTurn` 执行；令牌和执行时长仍由原运行时累计治理。本轮未增加跨进程团队、持久团队收件箱或共享工作区冲突合并能力。

## 验证与证据

证据目录：`evidence/2026-10-22-subagent-reliability/`。

- `red.txt`：未修复生产实现上的首批 9 个失败场景。
- `red-followup-cleanup.txt`：连续追问拼接旧答案、失败轮次返回旧答案、父退出未取消子任务三个修复前失败。
- `red-history.txt`：控制面无限保留终局代理的修复前失败。
- `red-cancel-followup.txt`：追问执行中取消时，错误返回上一轮答案的修复前失败。用轮次检查点归属校验修复，尚无本轮检查点时不输出上一轮文本。
- `budget-acceptance.mjs`、`red-role-budget.txt` 与 `green-role-budget.txt`：角色迭代上限的独立验收。原实现通过内存编译 HEAD 的控制面及交互 worker 复现，同样的依赖与供应商脚本下原实现请求 3 次，修复后限制为 1 次并返回失败终局；不替换工作区或运行中的构建。
- 后续绿色验证及完整质量门禁输出保留于同目录；仅依据最终输出填写结论。

验证采用脚本供应商及手动计时器，检查答案内容、请求实际模型/提示词、取消、终局、订阅计时器释放与队列容量，不用休眠竞争证明时序。真实模型协作质量、Desktop 原生接线、安装包与外部软件操作不由这些测试证明。

## 自审

1. 可读性：控制工具只负责命令编排，轮次观察独立成模块；新增请求使用具名字段，避免原来位置参数混淆。运行时原有大文件仅增加统一取消入口，不混入轮次或 UI 状态。
2. 可维护性：不新增执行循环，失败判定复用一个函数。通道容量、观察超时及历史容量都有明确归属；观察计时器、信号订阅在 finally 中释放。
3. 架构：主循环、供应商协议、标准生命周期枚举未改变；新增 `results` 是控制工具的兼容性扩展，不成为第二份终局写入源。
4. 正确性：逐项验证答案内容、跨轮次去旧、角色与模型接线、等待总截止时间、取消与退出清理。取消不提前释放 worker 的并发槽，沿用原运行时的真实退休语义。
5. 安全：未扩大子工具范围，未新增独立审批或从模型文本推导授权；原有工具边界、并发与治理回归必须通过。
6. 供应链：未增加或更新依赖，未复制第三方实现；本轮原实现对比来自本地已追踪 HEAD。许可检查以完整门禁输出为准。
7. 证据：修复前失败分别保留，脚本供应商与真实模型边界明确。禁止由部分工程检查推导 WP22 全量成熟或真实供应商验收通过。

## 环境诊断与最终门禁

首轮 `verify.txt` 完整运行但失败。静态扫描把工具说明中的英文 `as any` 误识别成类型断言，已改写说明并以 `hygiene-recheck.txt` 证明无扫描问题。另有临时目录的 `ADMINI~1` 短名与 `Administrator` 规范长名不一致，导致未修改的工作区相对路径和 cwd 断言失败；在仅对子进程设置规范 TEMP/TMP 后，相关 37 个检查通过，见 `canonical-temp-probe.txt`。不修改系统或 Desktop 环境，也不把测试环境调整记为产品路径修复。

完整首轮日志、发现列表和失败结论继续保留。第二轮 `verify-canonical-temp.txt` 除最后补出的取消追问回归外无其他失败；该轮使用的是最后检查点修复前的编译模块，不作为最终验收。

最终 `verify-final.txt` 使用全部修复后的构建及规范 TEMP/TMP，11 项门禁全部通过，耗时 258.72 秒，hermetic discovery 记录 4250 个测试条目。`targeted-final.txt` 单独记录 85 个子代理相关检查全部通过，耗时约 1.23 秒；最终角色迭代预算验收见 `green-role-budget-final.txt`。严格构建、架构、规范契约、状态转换、许可闭包和源码检查均通过，差异空白检查通过。可读性与可维护性自审通过。

`artifact-binding.json` 绑定本轮 11 个源码/测试文件及各自编译产物的 SHA-256、构建输入、完整门禁和测试条目记录。原实现对比固定为 `3ac4383b545379d3b9cac0feb0a0f045b41ef030`，不随未来 HEAD 漂移。原始失败保留，最终结论以 `verify-result-final.json` 为准。

结论范围：新 CLI 工程层与脚本供应商下的多代理控制面可靠性修复完成；真实模型长任务协作、原生 Desktop 接线、安装包和完整团队系统成熟度仍不在本轮验收结论内。
