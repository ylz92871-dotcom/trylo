# 内置工具报复式审计 V3

日期：2026-10-23。范围：新的 CLI 内置文件读取、内容搜索、通配符、编辑、补丁、notebook 与前台管道。用户要求持续寻找可复现反例，发现后立即修复。

本轮采用逐轮反例、修复、换轴复验与自审；没有独立审计员或真实模型评委。保留 V1、V2 原始失败与冻结候选。没有修改当前运行的 Desktop/Service Host、全局 provider 或凭据，没有提交、安装或发布。

## 行为合同与边界

- `read_file` 保留默认旧调用的字节前缀，以及显式 offset/limit 的完整行分页、CRLF、BOM、UTF-8、totalLines、nextOffset 和 lineTooLong 语义。Node reader 流式读取；兼容原有仅提供整段字符串的注入 reader。为给出准确 totalLines，仍需扫描至 EOF，不能把内存降低误称为随机定位读取或恒定读取时间。
- 用户正则只在独立工作线程执行。启动预算 2 秒，每文件匹配预算 250 毫秒；取消、超时、成功和失败都由父调用终止并等待线程退出。超时为 `regex_timeout`，线程异常为 `regex_worker_failed`，语法错误保持 `invalid_pattern`。超时不伪造无匹配或完整搜索结果。工具描述告知恢复方式。
- 写入权限依旧由原 sandbox/Permission Service 决定。路径在排队前与锁内重新核对，检测父目录或物理目标变化；直接入口可能返回 `path_changed_before_commit`，补丁保持既有操作失败包装与已落盘/待处理说明。没有扩大访问模式或授予权限。
- 取消在补丁提交锁内检查。未落盘返回 cancelled；目标已写入但移动源尚未删除时，保留源并报告 apply_cancelled 及已写入目标。没有把部分改动描述成无副作用取消。
- edit_file 两种输入及 notebook_edit 的完整序列化结果均受 maxWriteBytes 限制，拒绝时保持原文件。没有静默截断。
- 通配符语法保持原有范围，匹配改为有限状态执行，避免回溯爆炸；新增 4096 UTF-16 单元和 32 层花括号深度限制，超限为 invalid_pattern。该修改也覆盖 include/exclude 共享的 glob 编译器。`.gitignore` 仍由原 node-ignore 实现，本轮不宣称其计算复杂度已验收。

## 六轮反例与修复

### 第一轮：输入内存与正则阻塞

旧实现读取两行仍调用整文件读取；禁止整文件分配、仅提供流的注入 reader 返回 read_failed。修复后直接读取流，整文件调用次数从 1 降为 0。真实 Node 文件探针使用 50,331,648 字节输入、offset 40000、limit 2：前后均返回 2048 字节、49152 总行、40001–40002 行。测得 JavaScript heap 增量从 54,793,592 字节降至 2,234,664 字节。数据是该独立进程的样本，不代表操作系统 RSS 上限。

旧正则 `(a+)+$` 在 40 个 a 加感叹号的输入上，连 100 毫秒的取消回调也无法执行；外部子进程 1.5 秒保护触发。修复后同一探针正常返回 cancelled。另有预算超时、后续健康搜索和既有语法回归。见 round1-red/green.json、read-memory-red/green.json、round1-tests.log。

实现把文本和流适配器统一到一处窗口选择策略，避免保留两套分页算法。1152 组初始字符/分块/旧调用组合通过；随后以冻结 V2 的纯选择器为独立参照，固定种子 12000 组显式分页对比零差异，见 range-fuzz-final.json。

### 第二轮：排队取消仍写入/删除

新增、更新、删除与移动在排队期间取消后仍会提交；移动的第二阶段在取消后仍会删除源文件。五条反例在冻结 V2 全红。检查移入锁内，父目录创建也推迟至取消检查之后。移动已写目标时，取消阻止后续源删除并保留部分改动记录。五条反例及相邻事务/补丁回归共 17/17 通过，见 round2-red.log、round2-green.log。

### 第三轮：目录替换与统一补丁大小绕过

排队回调将已审核父目录换成工作区外 junction，旧 write_file、edit_file 与 apply_patch/delete 都能改动外部文件。修复在共享队列中核对路径与物理目标；三个测试分别检查外部原文件和原目录内文件均保留。

统一补丁格式 edit_file 原先没有在计划中携带 maxWriteBytes，8 字节上限可以成功写出 101 字节。现在所有编辑格式检查最终内容。见 round3-red/green.log。

### 第四轮：notebook 最终大小缺口

notebook_edit 原先在 256 字节上限下成功写出 1183 字节。计划携带上限，序列化后、原子替换前拒绝超限，原文件逐字节保留。见 round4-red.log、round5-green.log。

### 第五轮：后段参数无效时提前启动管道

Node 对含 NUL 的参数同步抛错，旧的逐段启动允许先尝试启动 producer，随后才发现 receiver 无效；工具入场也未拒绝这种字符串。现在计划对 command/steps/pipeTo 做 NUL 拒绝，底层管道在任何启动前检查全部 argv。两条反例冻结 V2 全红，修复后启动计数为 0，见 round5-red/green.log。这里不将该输入验证等同于所有操作系统启动失败的原子事务保证。

### 第六轮：glob 的隐藏回溯爆炸

`*a` 重复 24 次再接 b，对 80 个 a 的文件名，旧编译正则在受保护子进程中超过 1.2 秒仍无返回。替换为有限状态匹配，每个字符的状态集合去重，用户星号不进入回溯正则；字符类仍用单字符正则验证，不包含用户重复语法。

原型在首次随机对比中错误允许末尾换行前结束，已移除该分支并保留 glob-fuzz-initial-failure.json。最终以冻结 V2 参照，包含中文、表情、换行、花括号、字符类与路径分隔符的 45000 组比较零差异。超长/过深图样返回 typed error，见 round6-red/green.json、round6-tests-red/green.log、glob-fuzz-final.json。

## 自审与剩余边界

- 可读性与维护性：读取窗口、正则线程生命周期、路径检查、glob 状态机各有独立 owner；文本与流共用选择策略；没有新增依赖或全局状态。
- 架构与安全：修改在 adapter 与原计划边界，核心执行循环和 Permission Service 无新增权力；不自动重跑副作用，不吞掉部分落盘事实。
- 证据：红例先于修复，磁盘内容与返回码分别检查；随机测试对比冻结旧实现，没有仅拿新实现自证。
- 锁内路径复核收口排队期间的替换窗口，不能宣称已消除外部进程在后续系统调用之间制造的所有 TOCTOU；那需要目录句柄/操作系统级能力约束。
- 内存样本仅针对 read_file Node reader。read_notebook、PDF、图像、后台/PTY 及第三方 MCP 仍有各自的资源与生命周期合同，不外推本轮结论。
- 浏览器、Windows MCP、真实 provider 长任务、原生 Desktop/WebView2、安装包与设备不在本轮验收范围。当前运行客户端未被替换。
