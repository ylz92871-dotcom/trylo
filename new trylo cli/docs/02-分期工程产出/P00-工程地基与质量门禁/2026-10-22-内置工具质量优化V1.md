## 结论与范围

本轮检查确认了内置工具的具体可靠性缺陷，不能由此推导“所有工具都低质量”。本轮修改新版 CLI 的只读搜索与命令执行适配器；读文件、精确编辑和 patch 路径纳入相邻回归。浏览器、Windows 操作工具、旧 CLI、运行中的 Desktop、安装包和用户模型配置不在修改范围。

真实调用链为 CLI `wiring` → `createReadOnlyTools` / `createMutatingTools` → 现有 workspace/sandbox 边界 → 搜索或命令适配器。现有权限、会话、进程 owner 保持不变。未引入第三方实现、依赖、工具执行新权限或学习行为。

## 修复前反例与行为合同

`evidence/2026-10-22-builtin-tool-quality/red-tests.log` 记录未修实现的 6/6 预期失败。未修编译输出保留在 `work/builtin-tool-quality-20261022/red-dist`，通过其中 `search.js` 的原始 `line.slice(0, 500)` 确认测试针对旧行为。

| 问题 | 修复后的合同 |
| --- | --- |
| 长行在第 900 列后才命中，返回的前 500 字符不包含实际命中，且不声明行被裁切 | 返回第一处命中附近的片段；长行附 `textStartColumn`（1-based UTF-16 单位）和 `lineTruncated`，总结果包含 `line_truncated`。普通短行维持原结构。 |
| NUL 二进制内容被作为源代码命中返回 | 内容搜索跳过 NUL 文件，返回 `skippedBinaryFiles` 与 `binary_file`，不伪称完整覆盖。UTF-16 文件不在 UTF-8 搜索支持范围。 |
| 搜索直接整文件读入，文件数量限额不能限制单文件体积 | 默认单文件最多 1 MiB；先 stat，Node 适配器再进行至多上限 + 1 原始字节的读取，处理 stat 后增长。超限计入 `skippedLargeFiles` / `file_size_limit`，其余普通文件继续搜索。 |
| 连续命令只返回最后一步 stdout/stderr，前一步的截断事实丢失 | 按执行顺序累计各步 stdout、stderr，分别受原有输出上限约束；任一步截断后总结果保持截断。 |
| 后续命令非零退出时，前一步诊断信息丢失 | 在首个非零退出处停止，错误保留已执行步骤的输出，不执行剩余步骤。超时路径同样使用累计输出。 |
| 后台管道只启动 producer，却向模型返回启动成功 | 现有后台注册表只支持一个 argv；检测到结构化管道或多步骤时返回既有 `background_single_command_only`，拒绝发生在任何进程启动前，并提示前台管道或单脚本后台方案。 |

读取适配器同时把 AbortSignal 传入 Node 的文本和媒体读取。取消、超时、非零退出继续使用原合同；不自动重试副作用、不猜补模型参数。

## 兼容性与维护性自审

- 工具名称和入参 schema 保持不变。搜索新增可选 hit 字段、跳过计数和不完整原因；`glob_files` 不读内容，行为保持不变。
- `FileSystemReader.readFileUtf8Bounded` 和 `maxSearchFileBytes` 是可选的适配器能力/配置，旧注入 reader 仍可编译。旧 reader 使用 stat + 读后字节检查；其读取中内存界限依赖 reader 自身，严格 IO 上限由 Node reader 实现。
- 工具说明更新会改变 catalog 指纹。既有持久会话若拒绝 catalog 不匹配，按已有 `--migrate catalog` 流程迁移，不绕过冻结检查。
- `search-content.ts` 只拥有内容准入和片段选取；文件权限仍由共享 resolver 决定，遍历仍由原 walker 决定，输出裁切复用现有 `truncateOutput`。
- 新 helper 没有全局状态、环境读取、依赖引入或权限决策。句柄在 `finally` 中关闭；IO 失败保留 `unreadable_file` / 类型化失败，取消由外层统一终结。
- 对现有较长的搜索/命令分派函数进行可读性复核：它们继续各自拥有一次操作的状态，未引入跨 owner 回调或循环依赖。没有为本轮预造通用工具框架。

## 已知限制与下一轮候选

1. 搜索仍受 500 文件、深度与命中数量等现有限额约束；本轮完善反馈，没有宣称大仓库全量检索或速度提升。JavaScript 正则仍与调用方共用事件循环，复杂正则的时间隔离尚未处理。
2. `read_file` 原有整文件读入再选行的 IO 方式未在本轮重写；搜索的新上限不等同于所有文件工具的输入内存上限。
3. 前台进程 spawner 仍在命令结束前累计输出，再执行裁切；持续大量日志的内存有界捕获是后续优先项。本轮修复的是多步骤之间的输出保留，不声称解决该风险。
4. 既有 Windows 短路径/别名导航问题已保存反例；本轮验证使用长路径。没有将环境修复冒充产品路径修复。
5. 后台管道现在准确拒绝；未新增多进程后台会话能力。已有单命令后台、轮询、停止与真实退出码另做平台回归。
