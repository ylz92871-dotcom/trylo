## 行为合同

首个问题是成员交接缺少可核对的产物、验收依据或未解决事项，接收成员因此重复调查或返工。输入保留成员身份、分工、交接、实际发送和执行结果的因果关系。只有有依据的配合方式缺陷才形成带适用条件的协作做法；成员执行失败、能力缺口和原因不明必须单列，不以 completed 推断质量。

完整路径是：真实团队执行采集 → 内部选择问题与分析 → Board 记录版本化做法与证据 → 后续真实成员派发采用有界建议 → 独立结果与明确纠正回写 → 下一次选择受到影响。首版学习交接，合同保留同步、分工、复核这些协作对象，不预先实现多套分析器。

独立调用只点名 collaboration 子系统并提供工作额度；调用方不指定学哪条经历或生成哪种做法。子系统自行选择未处理证据并决定学习步骤。预算用有界工作单位表示，纯确定性分析不冒称模型 token；上场内容另外有字符硬顶。Board 的时机调度可以随后调用同一入口。

## 状态与边界

| 对象 | 所有者与接口 |
| --- | --- |
| 成员、轮次、任务状态、交接投递 | 现有 SubagentRuntime / ControlAgentSessions；仅增加可选传感器和建议接点 |
| 工具权限、父级审批、角色能力地板 | 原 Permission Service 与冻结团队设施；学习输入和产物没有授权字段 |
| 学习事实和不可变资产版本 | 现有 Board 的单 writer、锁、序列、日志、重放与快照 |
| 证据选择、问题归因、条件编译、反馈更新 | collaboration 子系统；只经 Board 端口存取，不设第二本学习账 |
| 验收 | 独立结果检查器；成员自述与生命周期结束均不能替代验收 |

新增 collaboration 领域合同和版本化协作事实。做法复用 Board 的 workflow 资产外壳，由内容 discriminator 区分普通 workflow。首版是可撤销的有界试用，不自动晋升 active、不争用现有 workflow 激活指针、不改变执行核心。不兼容的内容不进入成员提示词。

## 失败、隐私和兼容

- collect 关闭时不采集、不学习；保留原运行恢复事实的责任不变。未开启本子系统的调用方保持原路径。
- Board 不可读、损坏、写入失败、超额度、取消或过时事实必须明确返回原因；执行可以降级继续，但不能把未落盘或未发送的建议报告成采用。
- 旧快照缺少新增字段解释为空；出现但非法的字段拒绝解码。旧版运行时不保证读取新版日志，回滚前应保留日志并使用未开启协作学习的新进程，不能删掉未知事实伪造兼容。
- 相同命令重试幂等，不同内容复用身份拒绝。孤立反馈、跨范围引用、无实际采用的结果不能增强做法。
- 明确纠正须带证据和作用域：仅本次、某类场景、长期变化。不得把局部例外扩为全局撤销，不得自动写 User Model。
- 只保存本任务所需的有界摘要与引用，不保存密钥、隐藏推理或无限完整上下文。

## 验证与交付

1. 合同与回归：解码、旧快照、Board 重放、冲突、孤立反馈、范围、额度、采集关闭、真实采用与纠正优先级；新增回归保留红例证据。
2. 实际场景：隔离工作区运行现有团队/子智能体设施；对照缺交接和采用后任务，独立检查交接质量、返工或交付变化。
3. 迁移：表面不同、必要条件仍成立的任务实际采用；避免误用：相似任务但前提不成立时保持沉默；纠正：下一次相关派发行为可见变化。
4. 工程门禁：类型检查、相关测试、架构/静态与许可证门禁、可维护性自审。真实 provider、原生 Desktop、安装包和总体产品能力分别标明证据边界。
5. 记录实现入口、调用示例、命令与原始运行证据、限制、回滚方式。本轮不提交、不覆盖其他任务改动、不新增依赖。
