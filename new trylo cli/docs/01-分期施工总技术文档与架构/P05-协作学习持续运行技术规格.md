## 目标与完成条件

交付可在普通团队和现有 Desktop 日常积累、采用并修正经验的协作学习子系统。一次交接成功、固定角色模板、规则文档或局部测试不构成完成。必须同时闭合自动采集、领域内部有界学习、持久资产、父级规划与成员协作消费、采用事实、反馈更新和重启恢复，并交付可运行构建与真实连续多成员证据。

用户已明确扩展到任务分解、分工粒度、交接内容、同步时机、信息共享、复核安排、等待与返工。首版交接案例继续验证，但不得用该案例代表完整范围。原生 Desktop、打包构建、真实 provider 与目标回归分开登记，未完成的链路持续施工。

## 现有设施审计与复用

- 使用当前冻结团队/角色、SubagentRuntime、ControlAgentSessions、输入队列、任务依赖准入、通信、上下文窗口、Tool/Permission 与恢复设施。领域不直接启动成员或执行生产工具。
- 现有 Board 是唯一学习 writer；事件序列、锁、幂等、快照、损坏拒绝与重放沿用。持久协作资产继续用 immutable workflow 外壳，内容 discriminator 区分 `collaboration-practice/v1` 与 `/v2`，不占普通 workflow active 指针。
- 父级建议复用现有有界学习消息槽，成员建议复用轮次 callerMessages；两者都在现有请求预算之内。不得在已预算请求后拼接无限经验，也不得把领域分析塞入 Execution Loop。
- Desktop 当前 `--learning=user` 不自动等价于 `all`；新增独立协作额度与开关，保留用户学习语义。不得借此改变工具授权、角色能力或批准状态。

## 领域合同与证据

V2 权威合同为 `learning/domains/collaboration/v2-contracts.ts`；严格解码和同一 Board 关系守卫负责收敛，不开第二本变体账。

| 对象 | 唯一职责 |
| --- | --- |
| Event | 带任务图/成员身份、条件、维度、因果引用及有界摘要的事实；运行时和 peer claims 区分 |
| Episode | 关联真实 event，保留交付、交接完整度、返工、等待和成本；缺失保持未知 |
| Practice | 问题族、假设、替代归因、辨别证据、适用条件、行为操作、失败条件与源版本 |
| Exposure | 实际 provider 发送确认后的版本、操作、上下文和文本 hash；展示不算采用 |
| Adoption | 原协作操作被现有执行设施接受并发生的事实，关联 exposure + action + runtime events |
| Outcome | 采用后经历与结果；peer_report 不具有 external quality pass 权力 |
| Correction | 本任务/任务类/精确 workspace 的 suspend/restore，恢复显式关联旧纠正 |
| Cycle | 同一 requestId 的额度、步骤、保留调用、实际/未知成本、游标与终态，负责学习恢复 |

归因必须同时考虑能力缺口、任务困难、配合方式与未知。一次失败不能给成员定级；模型自述、provider 429 和运行时终态都不能代替因果验证。模型输出只形成有来源的试用假设，事实引用不等于因果已成立。独立验收通过须来自真实检查器或明确用户通道。

模型生成有条件的行为 IR，不以新增固定角色模板代替学习。操作限定为 split_task、assign_member、request_context、synchronize、share_reference、schedule_review、wait_for_dependency、replan，分别作用于八个协作维度。父级操作是对原规划工具的提议，成员操作不能扩大分工或权限。对具体角色、任务族、依赖、配合方式、困难程度与成员数按结构条件选择，未知不能充当已知匹配。

## 有界循环、成本与恢复

外部仅点名 collaboration 并给额度；requestId、scope 和取消信号是宿主身份，不是代替子系统选题。子系统自行选择尚未处理的经历和反馈，生成/校验证据、提议试用或修订，并更新内部游标。

额度包含 maxSteps、maxModelCalls、maxModelTokens、maxPromptChars。每次模型调用前先在 Board 保留额度和源窗口身份；中断后的未知调用不退为免费。模型 usage 与保守记账分开保存：已报告的真实 token/耗时照实记；缺报告只记 unknown 并保守占用剩余调用额度。输入按有界窗口和保守估计准入，provider 只提供输出硬顶；如果实际 total usage 超出预估额度，记录真实超额、明确失败并停止，不能夹紧数字伪造预算遵守。

学习 provider 复用原配置和 credential resolution，但持有隔离 continuation，工具表为空。工具请求、非法 JSON、越界引用、越权内容、usage 非法、取消、超时或采集撤销均不能形成资产。学习取消不取消团队执行；成员取消、失败和任务中断仍由原设施推进。可选观察器失败不能改变执行答案或阻断终态/退休。

同一稳定宿主 requestId 的同额度重放不重新领钱；改额度也不能借重启清零。`resumePending` 仅从持久运行/保留状态继续原额度，不能恢复用户工具、重启成员或伪造反馈。已取消/完成的循环不得静默自动重开。新显式用户团队任务可由宿主发新 requestId 和新额度。

## 普通团队与 Desktop

普通冻结团队默认领取一段有界协作额度，可通过独立 `--collaboration-learning=off|<token-budget>` 关闭/限定。无团队不构造此域。Desktop 用单独 settings.collaborationLearning 传同一合同，提供启用和额度入口；不得把用户学习开关升级成 all。no_collect、collectNewLearning=false 和 session_only 隐私指令优先关闭采集与采用。

Host 在 provider 已构造后组合学习服务；start/wake/drain/close 属于学习侧生命周期，在团队边界或安全空闲机会调用同一独立入口。执行传感器仅落事实/通知，不做领域分析。生命周期要允许已有合法资产先用于工作，避免后台故障拖成成员失败；待处理学习在正常退出、中断和新进程启动时按账恢复。

父级消费必须证明分解/派工/复核等原操作实际改变；成员消费必须证明索取信息、共享引用、等待或同步实际发生。单纯在工具参数填 learning_action_id 不足以证明全部行为：split_task 至少关联多个实际子任务，schedule_review 关联独立复核成员与目标产物，其他操作检查其真实接收者、依赖和投递事实。现有主责/权限检查始终先行。

## 验证与交付门

1. 合同/存储：V1 兼容、新字段非法拒绝、引用/身份、资产不可变、幂等、并发、额度预留、中断与重启恢复；所有新增回归保留有效红例。
2. 执行：普通团队和 Desktop 的参数/隐私/冻结身份/有界槽/父级与成员实际采用；成员失败、provider 失败、取消和观察器故障不能改归因或状态权力。
3. 连续真实任务：至少多个连续团队批次，含多个成员、共享材料、依赖交接和独立复核；独立记录首交质量、返工、等待、模型成本和最终交付，报告失败/限制，不挑一次成功代替日常链路。
4. 行为：跨任务迁移、前提不同避免误用、明确纠正后的下一次实际行为、负反馈修订、预算/中断/重启恢复。自动 driver 真正发生学习，不能由验收脚本手工指定要学的资产或挑选成功产物。
5. 工程：可读性维护性自审与独立边界审查；目标回归、静态/架构/许可证门禁；CLI 和 Desktop 可运行候选、实际入口与打包证据。共享工作区的其他任务修改不得覆盖或清理。

当前 V1 的 335 项回归、观察器修复及真实失败是基础证据，不能直接继承成上述扩展门的通过结论。施工与验收继续在 P05 产出目录追加。
