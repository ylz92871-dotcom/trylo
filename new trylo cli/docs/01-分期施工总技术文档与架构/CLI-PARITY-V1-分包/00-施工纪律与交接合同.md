## 1. 第一门禁：代码纪律

施工与审查显式使用 [$trylo-code-quality](<D:/CC/trylo/new trylo cli/.agents/skills/trylo-code-quality/SKILL.md>)，并先读最近 AGENTS.md、[文档权威入口](<D:/CC/trylo/new trylo cli/docs/README.md>)、[可读性与可维护性纪律](<D:/CC/trylo/new trylo cli/docs/00-总领/代码可读性可维护性与审计纪律.md>)、当前总规格和本包。用户已授权复用并免去许可证检查；来源版本、最小运行/构建闭包、制品落点、类型边界和替换路径仍要留账。用户后续明确决策优先于本合同。

可读性和维护性不通过时，其他绿门不能抵消。函数只保留一个抽象层级；生产文件/函数/复杂度等按仓库现门禁执行，不提高阈值、不扩大白名单来放行、不手改 reachability、不删失败回归。runner/reducer/host 只做职责内编排，不继续堆跨域能力。

一个概念一个 canonical 类型，一个生命周期 owner，一个写入入口。Trylo Loop、Protocol、Permission、Session、Learning 仍各守原边界；领域不依赖第三方/UI/wire DTO。未知结果、部分发送、拒权、取消、超时、迟到事件、失败恢复用显式状态和终局。每个 catch 有 rethrow/类型化失败/注明清理合同，重复错误判定提共享模块。环境源和双重断言继续遵循原注入缝与白名单限制。

## 2. 一根线的施工顺序

1. 复核当前生产调用链和相邻测试，先跑适用前置门禁，红门先修。既有 green 是历史证据，不能免掉变更后的检查。
2. 写清行为合同、输入输出、状态 owner、提交点、失败/取消/timeout/unknown、兼容和不启用新开关时的旧行为。
3. 找到指定两基线的真实实现，固定 commit/hash，取最小必要闭包。复制/sidecar 直接复用原算法，只在类型、配置、IO和生命周期周围做薄桥。
4. 新增合同回归先对未修复代码留红证据；新增门禁另做违规注入。测试以行为、实际副作用、状态转换为目标。
5. 接一根线并证明用户入口→模型/工具→权限→实际动作→持久事实→可见结果；不 import open/，不让 fake/fixture 进入生产图。
6. 跑合同、组合和适用真机检查，先修可读性/边界问题，再按现规则独立 reviewer 复核，修复发现的问题并复验。
7. 记录范围、source/hash、新旧合同、红例、绿例、平台、限制和回滚 patch；再据证据更新主矩阵成熟度。

许可证检查按用户豁免不执行。若沿用此前临时验证 runner，记录“10项工程检查 + 第8项用户豁免”，不能改称原11/11。复用审计不继续搜索许可证。dirty tree 是用户成果，只做本包可复核的小变更，不 reset、不覆盖其他包、不整搬旧 lockfile。

## 3. 主责、接口前置与集成依赖

R1–R10 是原领域主责；WP01–WP26 是具体施工主责。[能力分包映射](<D:/CC/trylo/new trylo cli/docs/01-分期施工总技术文档与架构/CLI-PARITY-V1-分包/能力分包映射.json>)保证 172 个 ID 每个只有一个主交付包。WP27/WP28只验收，不新增或抢占主责；相同底层机制实现一次，其他ID的 owner 消费其端口。

每包“接口前置”要求相关接口已有版本化合同、真实可执行 adapter、失败语义和交接证据后，才接入消费方；不要求提供方整包全部验收才能推进。前置表是无环 DAG。它不替代总规格的领域顺序，只细分可交付边界。

“集成联验”列出必须参与的跨包组合。这些连接可能双向，但不构成“双方等对方整包完成”的开工循环。先固定边界，各 owner 接自己的 adapter，再共同联验；缺实际消费者就保持该能力 partial，不把接口或 mock 当闭合。WP27逐根核对，WP28只接受完整真实候选；发现 source_missing 或外部阻塞，保留目标和未完成状态。

包内列出的端口名包含职责占位；先找语义和寿命相同的既有合同，优先复用，只有确有缺口才新增 canonical 类型/端口并补兼容说明。不能照文档凭名字重复造第二套服务。
