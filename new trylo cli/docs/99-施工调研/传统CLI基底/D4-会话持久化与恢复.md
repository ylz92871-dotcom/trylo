# D4：会话持久化、崩溃恢复、历史压缩与文件回滚

## 0. 一页结论

- 写介质三路线：SQLite 事件投影（opencode、goose、cline manifest、codex state_db 索引）、JSONL 追加（codex rollout 权威、gemini）、全量 JSON 重写（mini、cline messages、aider 靠 git+markdown）。没有一家用"副作用重放"做恢复。
- 落盘带序号+内容校验的只有 Trylo（journal.checksum sha256）与 codex（ordinal 序号）；其余靠自增 rowid/时间戳，无内容级 checksum。
- UI 投影 vs 模型历史分离最彻底：opencode（event→projector→part + filterCompacted）；codex 用 ThreadHistoryMode；其余混写。
- 压缩阈值：opencode `count>=usable()`；goose 0.8；gemini 0.5/保 30%；codex Compacted+window_number；mini 无 compaction。
- 文件回滚成体系两家：cline（checkpoints ref + 事务）与 aider（git sha + cmd_undo）；opencode/gemini 快照式；codex 仅截对话历史；goose/mini 无。
- Trylo 缺口：无磁盘 session 持久化、无 compaction、无文件 checkpoint、无 markdown 导出、无跨版本迁移、无多会话锁、无读时 repair。

## 1. 存储介质与写时机矩阵

| 项目 | 权威介质 | 索引/副本 | 持久化点 | flush |

## 3. 崩溃恢复流程（codex/goose/cline）

**codex**：state_db 选择器→回退扫目录；load_rollout_items 逐行反序列化统计 parse_errors(跳坏行)；reconstruct_history_from_rollout 按 Compacted.window_number 划窗只重建有效窗口；thread_rollout_truncation 用 ThreadRolledBack 回推有效历史；副作用不回滚(已定稿 ResponseItem)；看到恢复对话含 summary 段。

**goose**：SQLite 读 Conversation→发送前 fix_conversation/fix_tool_calling(悬空 ToolRequest 从 assistant 删、孤立 ToolResponse 从 user 删，返回 issues，非合成)；停在待确认则 pending_tool_confirmations/resume_from_persisted_response 走 state-machine resume；legacy .jsonl 首访迁入 DB。

**cline**：readMessages→trimMessagesBeforeUserRun 按 checkpointRunCount 截断→agent-runtime.restore(abort 在跑 run、清 runId/status/iteration/pendingToolCalls、usage 归零、lastError 清、保 listeners/model/tools)→beginWorktreeRestoreTransaction(stash push --include-untracked→私有 ref→clean -fd→commit/rollback)+applyCheckpointToWorktree；fork 新 session 不删旧。

## 6. 文件回滚 vs 对话回滚

| 家 | 对话回滚 | 文件回滚 | 原子 |
|---|---|---|---|
| cline | trimMessages fork 新 session | checkpoints/{sessionId}/{runCount} stash commit+第三父 untracked；事务 | 两步分离(restore.messages/workspace) |
| aider | chat md 文本 | cmd_undo 逐文件 checkout HEAD~1+reset --soft | 对齐非同一事务 |
| codex | ThreadRollback{num_turns}+truncate_rollout_before_nth_user | 无(仅 TurnDiff 展示) | 仅对话 |
| opencode | revert{messageID,partID,snapshot} | Snapshot.track/restore/revert(patches) | 快照式非 git |
| gemini | RewindRecord.$rewindTo | shadow-git createFileSnapshot+/restore | 对话+文件快照 |
| goose | 截 conversation | 无 | — |
| mini | 无 | 无 | — |

git 权威=cline+aider；快照式=opencode+gemini；纯截断=codex+goose。

## 7. 多会话与并发

| 家 | 隔离 | 锁 |

| codex | 每会话一 rollout 文件 | WriterLockCoordinator thread-writer-locks/{thread_id}.lock(WouldBlock)+.coordination.lock |
| goose | 每 session 一行+FK | DB |
| cline | 每会话 .messages.json | sessions 表 pid+status_lock |
| gemini | 每 sessionId .jsonl | 无 |
| aider/mini | 单工作树/单实例 | 无 |

Trylo：journal 进程内数组无 session 锁；learning/permission-store 有文件锁但不在 loop 路径。

## 8. 导出与互操作

- markdown：goose export_markdown(tool_request/response_to_markdown，export_all_content)；cline/aider chat md(aider 既产物又是 --restore-chat-history 输入)；opencode share/session_diff JSON。
- 跨版本 resume：codex ThreadHistoryMode{Legacy,Paginated}+Compacted 缺 window_number fallback；gemini .json→.jsonl 归一化+message version 同步；opencode storage MIGRATIONS+drizzle migration 双轨；cline session-import；goose legacy.rs 补默认字段；mini trajectory_format/mini_version 标记但无 resume。

## 9. Trylo 现状

已有 ExecutionJournal(内存+serialize/parseJournal)、envelopeChecksum+verifyJournal、replayCommitted、domain/replay、codec.encodeEnvelope。注意 serializeJournal 只在 index 导出、runner 返回 journal.events()/inputs()——loop 内无任何 node:fs 写 session(写全在排除的 learning/knowledge/permission-store 侧)。

## 10. Trylo 缺口

1. 无磁盘 session 持久化(退出即失)。
2. 有 verifyJournal 却无读回调用。
3. 无 compaction(无阈值/summary/读时过滤)。
4. 无文件 checkpoint/回滚 UI。
5. 无 markdown 导出/无 version 迁移(仅 PROTOCOL_VERSION="0.0" 常量)。
6. 无多会话锁。
7. 无读时 repair(goose fix_conversation 式净化，可用 checksum 截到最后一个 verified envelope)。
