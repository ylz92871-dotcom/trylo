# D5 多表面架构（server/client 分离、ACP/ag-ui 投影）与子代理

> 调研根 `open/`（OPEN）。引用符号均先 Read 再引：Trylo 锚点 `src/internal/protocol/{envelope,kinds,codec,sequencer,redact,validate,compat,terminal}.ts`、`src/internal/journal/{projection,whitelist}.ts`。
> 结论先行：**「core 是事实源」在六家里是三档强度不同的实现；子代理审批没有一家给独立通道；Trylo 已具备投影「输入端」（envelope/sequencer/redact/journal 投影范式），缺「输出端」（传输面、协议 codegen、per-kind payload 契约、子代理血缘字段）。**

## 1. 「core 是事实源」三档强度：loop → 远端 UI 的跳数与序列化点

### 1.1 opencode（HTTP server + SDK codegen）
- 事实源 = 单一 `HttpApi` 组合根 `packages/opencode/src/server/routes/instance/httpapi/api.ts:79-84`（`OpenCodeHttpApi.addHttpApi(RootHttpApi/EventApi/InstanceHttpApi/ServerApi/PtyConnectApi)`）。一份定义同时长出「运行时路由 + OpenAPI + 类型化 SDK」：`server/server.ts:67-69 openapi() { return OpenApi.fromApi(PublicApi) }`；`packages/sdk/js/src/v2/gen/sdk.gen.ts:1` 首行 `// This file is auto-generated by @hey-api/openapi-ts`。
- 事件目录 current/V1 策略（`packages/schema/src/`）：`event.ts:15-25 Definition.durable?:{version,aggregate}`、`event.ts:76-92 latest()` 按 type 取最高 durable 版本、`event.ts:94-96 versionedType=\`${type}.${version}\``；`event-manifest.ts:34-37` 把 V1 一分为二——durable 部分进 `coreDefinitions`（仍为权威 journal），live 部分另并总表（`:63-82`）。**本质=版本化 event-sourcing schema。**
- 唯一投影出口 `handlers/event.ts`：`:31 Queue.unbounded`→`:32 events.listen(...)`（注释 `:29-30` 强调 eager 注册防丢事件）→`:35-41` **只按 directory/workspaceID 过滤，不按 session/producer**→`:70-78 Sse.encode()`→`HttpServerResponse.stream(..., contentType:"text/event-stream")`，`:17 JSON.stringify`。路由 `groups/event.ts:13-16 HttpApiEndpoint.get("subscribe", "/event", …text/event-stream)`。心跳 `:63-66 server.heartbeat`（10s），**无 cursor**。
- 三模式（`cli/cmd/run.ts:5-11` 注释声明）：默认非交互 `:948-961` 注入内存 fetch——`const fetchFn = async (…) => Server.Default().app.fetch(new Request(request, { headers })) as typeof globalThis.fetch; createOpencodeClient({ baseUrl:"http://opencode.internal", fetch: fetchFn })`（**走完整 HTTP/Effect 栈但不经内核 socket**）；`:834 client.event.subscribe()`→`:697 loop(client, events)` 消费。`--mini` 同一手法（`:910-917 runInteractiveLocalMode({ fetch: fetchFn })`）；`--mini --attach` 换真 TCP（`:349-353 attachSDK = createOpencodeClient({ baseUrl: args.attach! })`）。TUI 共用同一面（`packages/tui/src/context/event.ts` 等一律 SDK client + `event.subscribe()`，无第二私有通道）。
- **跳数/序列化点**：loop → EventV2 bus → per-subscriber Queue → **SSE encode(#1)** →（内存 fetch / TCP）→ **SDK decode(#2)** → UI。共 2 点；in-process 模式下两点之间无 socket。

### 1.2 codex（app-server JSON-RPC，连 exec 都走协议）
- 传输：`app-server/src/main.rs:39`「Transport endpoint URL. Supported values: `stdio://` (default), …」；`lib.rs:50-51` import `start_stdio_connection`+`start_websocket_acceptor`，`:774-775 AppServerTransport::WebSocket { bind_address } => start_websocket_acceptor(...)`。
- method 命名规范 = **noun/verb**（宏统一生成，`app-server-protocol/src/protocol/common.rs`）：`:559 "thread/start"`、`:565 "thread/resume"`、`:571 "thread/fork"`、`:1041 TurnInterrupt => "turn/interrupt"`；`serde(tag="method", content="params")`（`:1663`）。四族原语：`ClientRequest`（c→s 请求）、`ServerRequest`（s→c **反向请求**，§2）、`ServerNotification`（`:1892-2001` 巨大目录：`item/agentMessage/delta`、`item/reasoning/summaryTextDelta`、`thread/tokenUsage/updated`、`thread/compacted`、`model/rerouted`…）、`ClientNotification`。
- Notification 与 core `EventMsg` 的关系 = **显式无状态投影**，`protocol/event_mapping.rs:24-31` 原文：「Build the v2 app-server notification that directly corresponds to a single core event. … This only covers the **stateless** event-to-notification projections that have a **one-to-one** mapping. Callers remain responsible for any surrounding state checks」→ `item_event_to_server_notification(msg: EventMsg, thread_id, turn_id) -> ServerNotification`。**core EventMsg 是事实源，ServerNotification 是其一对一投影；有状态聚合留调用方。**
- experimental 门控：`common.rs:592 #[experimental("thread/increment_elicitation")]`、`:1906 "thread/queue/changed"`、`:1941 "process/outputDelta"`；并生成**运行时可查询**判定 `common.rs:393-408 impl ExperimentalApi for ClientRequest { fn experimental_reason(&self) -> Option<&'static str> }`（非仅编译期 cfg）。新旧同表并存（`:1795-1807` legacy `ApplyPatchApproval/ExecCommandApproval` vs `:1741-1793` 新 `item/*/requestApproval`）。
- `codex exec` 也在协议里：`exec/src/lib.rs:21 use codex_app_server_client::InProcessAppServerClient;`、`:973 InProcessAppServerClient::start(in_process_start_args).await`，之后一律 `ClientRequest`（`:985 ClientRequest::ThreadResume { request_id: request_ids.next(), params }`），**无旁路直调 core**。TUI 依赖的 Cargo 证据：`tui/Cargo.toml:32-33 codex-app-server-client = { workspace = true }` + `codex-app-server-protocol = { workspace = true }`。
- **跳数/序列化点**：loop→EventMsg→投影（无序列化）→**JSON-RPC serde 编码(#1)**→stdio/WebSocket 或内存队列→**解码 ServerNotification(#2)**→渲染。**特征是「序列化点数量与传输无关」**——内嵌与远端用同一组类型，只差最后一跳 socket vs 队列 → 「core 是事实源」被实现成「**协议类型即唯一事实源**」。

### 1.3 cline（hub daemon 独占持久 journal + cursor replay）
- 发现/传输：`sdk/packages/core/src/hub/discovery/defaults.ts:11-13` `DEFAULT_HUB_HOST="127.0.0.1"` / `DEFAULT_HUB_PORT=CLINE_HUB_PORT` / `DEFAULT_HUB_PATHNAME="/hub"`；配 `discovery/instance-lock.ts`（单例锁）、`daemon/entry.ts:32`（注释「Resolves only after the daemon WebSocket server is listening…」）、`server/hub-websocket-server.ts`、`client/{connect,session-client,ui-client}.ts`。wire 三相 `approval-handlers.ts:1-6`：`HubCommandEnvelope / HubEventEnvelope / HubReplyEnvelope`。
- **事实源 = 带全局序列的持久 log**：`hub/server/hub-event-log.ts` 文件头注释原文（`:2-8`）「**Durable, cursor-addressed Hub event log.** … increasing global sequence before it is fanned out to live sockets … `sinceSequence` on `stream.subscribe`: the adapter replays pages from this …」；`:78 sequence INTEGER PRIMARY KEY AUTOINCREMENT`；`:92-94`「Append a durable event and return it stamped with its global sequence. … live listeners and replaying clients observe **identical frames**」；`:109-112`「Stored without `sequence`; stamped from the rowid」。→ **序列化只在入 log 前一次，live 与 replay 复用同一批字节**。六家唯一把「事实源 = 持久序列 log」（而非进程内存）显式做出的实现，与 Trylo journal 最同构。
- VSCode 是**另一条 client 面**（非第二事实源）：`apps/vscode/src/core/controller/grpc-handler.ts:3-4,25-29,63,87-101`（`GrpcRequestRegistry`、`response.grpc_response.request_id`、`if (request.is_streaming)`、`type:"grpc_response"`），gRPC/protobuf 与 hub WS 并存。
- **跳数**：loop / `SessionRuntime.onEvent` → `session-event-projector`（补 agentId/parentAgentId，§4）→ `HubEventEnvelope` → **SQLite log 赋 sequence（持久化序列化点 #1）** → WS fan-out → client decode（#2）→ UI；断线走 `sinceSequence` replay。

### 1.4 小结

| 维度 | opencode | codex | cline |
|---|---|---|---|
| 事实源载体 | HttpApi 定义 + EventV2 bus（内存） | 协议类型（ServerNotification/ClientRequest） | **持久 journal（SQLite+全局 sequence）** |
| in-process 是否仍走协议 | 是（`app.fetch` 注入，走 HTTP 栈） | 是（`InProcessAppServerClient` JSON-RPC） | 是（hub 仍是 WS 服务端，同 envelope） |
| 序列化点 | 2（SSE encode / SDK decode） | 2（JSON-RPC encode/decode），与传输无关 | 1（入 log 前）+ WS 帧 |
| 类型/SDK 生成 | `OpenApi.fromApi` → `@hey-api/openapi-ts` | 宏 + `JsonSchema`/`TS` derive（Rust+TS 双端） | `@cline/shared` envelope + proto |
| 断线重放 | 无 cursor（仅 heartbeat） | 靠 `thread/resume`（`common.rs:565`） | **`sinceSequence` cursor 分页** |

另：goose/gemini = 单 core + 多投影（ACP/ag-ui/a2a），无独立持久 log；aider = 无第二面（`aider/main.py:1159 while True:` 单进程循环，`--editor`(`:945`) 与 `FileWatcher`(`:1028`) 只是**同进程输入侧缝**，不产生控制面）。

**对 Trylo 的判读**：Trylo 现状 = 有 journal 语义、无 journal 面。`codec.ts:5-7 encodeEnvelope = JSON.stringify(envelope)+"\n"` 已 NDJSON；`sequencer.ts:11-25 createAttemptSequencer().bind()` 已给 per-attempt 单调 `sequence`；`validate.ts:26-28,86-95` 已校验 sequence 非负整数 + `payload<=MAX_PAYLOAD_BYTES(65_536)`（`envelope.ts:21`）。**缺的正是 cline 那层「全局 sequence + sinceSequence replay」与 codex 那层「协议类型即唯一事实源」。**

## 7. 「把别的 CLI 当 provider」（goose claude_code / codex_acp 桥）
机制一句话：**在 `Provider` trait 之下，把 goose 的 completion 调用改写成对另一个 CLI 子进程的 stdio 协议对话**——两种后端：
- (a) `providers/claude_code.rs:256`（注释「`--input-format stream-json --output-format stream-json`. The CLI stays alive…」）+ `:334-341 Command::new(&self.command).arg("stream-json")…` + `:383,402 spawn_process/child = cmd.spawn()`：**stream-json 往返**。
- (b) `providers/codex_acp.rs:22 CODEX_ACP_PROVIDER_NAME = "codex-acp"` + `use crate::acp::{AcpProvider, AcpProviderConfig, extension_configs_to_mcp_servers}`；实现落在 `acp/provider.rs:274 AcpProvider`、`impl Provider for AcpProvider`(`:677`)、`spawn_acp_process`(`:1480`)、`spawn_client_loop`(`:318,409`) —— **goose 作为 ACP 客户端去驱动一个外部 ACP 适配器进程**。
→ 两种都是「把别的 CLI 当模型后端」，(b) 比 (a) 更规范（走标准 ACP schema 而非私有 stream-json）。

对 Trylo 早期价值：**低**。Trylo 的 provider 层（`src/internal/ports/provider.ts`）对接的是模型 API，不是另一个 agent；本机制只在 Trylo 决定**把自己暴露为 ACP agent**（§8 输出端）时才镜像相关——届时「ACP client 桥」与「ACP server 面」可共用同一份 schema/投影。结论：记录机制，不排期。
