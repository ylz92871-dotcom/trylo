# 参考资料区

这里保留外部公开资料的分类说明与来源索引，不是设计权威。原始来源卡位于仓库根 [`_workspace/archive/tracked/new-cli-reference-materials/`](../../../../_workspace/archive/tracked/new-cli-reference-materials/)。可以研究成熟项目的接口分层、异常处理、测试方法和工程取舍，但每一项都必须可追溯，且不能因为“仓库首页写了 MIT”就跳过文件级与传递依赖审计。

## 目录

- `MIT-可评估复用/`：MIT/ISC/BSD 等最宽松许可候选；通过边界和闭包审计后才可能进入产品。
- `Apache-2.0-可隔离评估/`：Apache-2.0 的 B/C/D 级候选，保存 NOTICE、最终制品位置、Trylo port 和替换性证据。
- `仅供研究-禁止依赖/`：来源不明、强 copyleft、商业限制，或因核心架构渗透尚未获批的资料。这里只能阅读和写独立设计笔记。

## 每份资料必须附带的来源卡

新资料与同名 `.source.md` 放在仓库根 `_workspace/research/<主题>/`，本目录仅维护导航。来源卡至少记录：

- 项目名、官方 URL、上游仓库 URL；
- 获取日期、commit/tag、文件路径和内容 hash；
- 仓库许可证、目标文件许可证、直接依赖和传递依赖结论；
- `直接采用 / 隔离采用 / 核心例外 / 仅供研究 / 拒绝` 五选一结论；
- 学到的设计点与 Trylo 自己的决策，不复制上游命名来冒充原创边界。

## 硬规则

- Apache-2.0 不是自动拒绝。进入产品前必须确定 A–E 架构等级；A 级核心例外要产品所有者批准，B/C/D 级要完成隔离、NOTICE/SBOM 和替换性审计。
- 任何未审计内容默认 `仅供研究`。
- 不在这里保存完整巨型仓库；优先保存官方文档、固定 commit 的少量关键文件、架构笔记和许可证证据。
- 参考资料不是权威需求，真正采用的设计必须进入 Trylo ADR 或当前期技术规格。
- 拉取资料不得包含令牌、用户数据或来源不明的二进制文件。
