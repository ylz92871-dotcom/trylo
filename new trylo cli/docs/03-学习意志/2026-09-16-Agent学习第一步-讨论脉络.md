# Agent 学习第一步：讨论脉络

> 日期：2026-09-16  
> 来源：产品所有者与施工对话（先讨论，后收缩成工作包）  
> 性质：所有者意志的书面脉络，不是施工包、不是外审  
> 对应施工包：`../02-分期工程产出/P05-Experience-Learning-V0.3/2026-09-16-WP-Agent学习调度器与本轮约束卡.md`  
> 本文件只记录已经说过、并且收缩后仍有效的判断。更深的（上场选卡、卡版本竞赛、hold、用户学习）标成「以后再讨论」，不在这里假装已定。

## 1. 谁决定学习包

学习这一块，产品所有者要亲自讨论再开包。模型自己决定时想得单点、发散不够，不准再「先写包再补讨论」。

传统 CLI 可以交给模型按 `docs/99-施工调研/传统CLI基底/` 做，所有者不必每包过一轮。

讨论过的学习思路必须落在本目录，因为人会忘，后面的 Agent 也会丢脉络。

## 2. 已经拍板的

**调度器是明珠。** 学习控制板与执行调度器平级。它发工单给对应学习系统，允许这轮花 token 向 LLM 发起学习请求。执行环不自己 `if (失败) 学习()`。

**这轮学什么。** 一张本轮有效的闭集约束卡（trigger + 枚举 constraint + 短 hint），不是 SKILL.md，不是用户偏好，不是造工具。路径逃逸只是例子。传感器至少两种（路径类失败、同参数指纹连撞），同一个 worker，不是一种失败一个包。

**不能一失败就学。** 第一次只记账。中间成功过就重新计数。再让执行自己试一拍。还撞同一指纹才发工单。同一 turn 最多一张 intra。任务最终成功的中途噪声默认不学。

**学习进程。** 工单批准后，intra worker 打一枪 LLM（扣学习预算，不调生产工具）。代码门：JSON、枚举、禁止权限/网络/装工具等词。过门才注入。下一拍真实工具结果说这张卡有没有用。模型不许给自己打分过门。

**注入。** 下一枪 `ProviderRequest.messages`，在现有 `promptMessages` 那一层加一条短 `system`（和压缩摘要同一张嘴：既不是用户说的也不是助手说的）。卡挂本 turn ledger，turn 结束从提示词拿掉。不改沙箱、不改权限、不减工具表。

**档案。** 有效的卡可以进 shadow。本包跨 turn 默认不上场，所以不会出现 system 越用越长。

**卡更新。** 以后是新版本 + 挪指针 + 记有用/没用，不原地改。本包不做更新器。

**传感器。** 用总领的词：执行钩子唤醒控制板。论文有「失败了才 intra」的同类思想，没有这块第二调度器。总领还说没有新传感器时板也可以因自己的钟而动。传感器以后会不够，以后再讨论。

**生产默认仍关学习。** 测试和显式开关才跑调度器。关掉必须和现网纵切字节级同一条干活路径。

## 3. 明确以后再讨论（本包碰了就算越权）

- 跨 turn 从档案挑 K 张卡上场（经验检索）
- 每回合用 LLM 当检索大脑
- 卡版本竞赛、自动改写 hint
- hold 打断用户当前 turn
- 用户学习深链
- 技能文件 / 工作流归纳 / 工具安装
- 冻结 Dispatch Image 名称和内容表

这些不是否定，是深度还没讨论完。所有者说讨论会越问越深，所以施工必须先收缩。

## 4. 对总领的推动（已写入总领短补）

- 提取（出新卡）和上场（这轮带哪张）都是控制板的事，不是往 system 里 append。
- 上场必须有硬顶；本包硬顶是「本 turn 最多一张，跨 turn 零张」。
- 学习类工作包必须先讨论，脉络进本目录。
