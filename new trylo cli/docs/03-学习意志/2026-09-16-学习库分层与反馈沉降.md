# 学习库分层与反馈沉降：入库不设门，沉降才要证据

> 日期：2026-09-16
> 来源：产品所有者否掉「独立审计 / 法官体系」之后给出的方向（当晚对话）
> 性质：学习库的**分层与反馈口径**（所有者意志的书面形式；施工前仍须有技术规格与工作包）
> 与 `2026-09-16-方法子系统-共枪标签钩子.md` 的关系：那一份管**方法子系统内部机理**，本文件管**库的层次与沉降**。两者冲突时以本文件为准，修订口径见 §7。

## 1. 先否掉什么

所有者明确否掉两件事，这是本方向的起点：

1. **不要「独立审计」这一套。** 原话：「我感觉不应该这样搞什么独立审计，这样不像学习。」
2. **不要自造一套「法官体系」，然后在一个静态池子里自以为是地优化。** 原话：「不要自己想了一套法官体系，之后就一直在在这个池子自以为是的优化，从开始那个法官体系就不好。」

理由：**学习不是审出来的，是用出来的。** 外挂一个裁判/审计机构，会把系统变成「先取信、再使用」；而学习应当是「**先使用，结果自己说话**」。

> 这一条同时作废了先前讨论中「判据分两区 + 人工审批判据」的整套设想，也作废了「把审计当成入库门槛」的做法。

## 2. 三层库

所有者给的结构：

| 层 | 是什么 | 特征 |
| --- | --- | --- |
| **活跃层** | 刚学到的东西**先入这一层** | 最新、最活跃、最容易迭代；**需要时就从这里抽卡** |
| **中间层** | 好用再往深了入 | 好不好用由**实际任务的反馈**体现 |
| **稳定层** | 之后运行里稳定的经验层 | 最底下那一层 |

原话：「你学到的东西先入一层库，这层是最活跃和最容易迭代的，然后它也是最新的，也就是之前提到抽卡，这里有需要是要从这里面抽，然后根据实际任务的反馈来体现它好不好用，好用再往深了入库，最底下那层就是之后运行里面稳定的经验层。」

## 3. 铁律：入库不设门，沉降才要证据

- **进活跃层不设任何门。** 它是暂存区，进它不影响任何东西。
- **只有「往深了沉」才要证据**，而证据**来自实际使用**，不是来自审计。
- 「独立」在这里的含义是：**让任务自己判**。任务不关心某个资产好不好，它只是跑；跑完成不成由它自己说。**任务天然独立，所以不必另设一个机构去模仿独立。**
- 沉降是**攒批**做的，不是每一条都过一遍。
- **不设门的只是「入库」。** 总领已定的三样——装工具、对外贡献、改权限——仍然永远要人点头；它们是不可逆的外部动作，与库的层次无关。

## 4. 活跃层的淘汰：按时间

原话：「活跃层满了就按时间淘汰呗，你没沉淀下去，那自然淘汰，按时间就行。」

- 活跃层有**容量上限**；满了由**最久没被用到**的先走。
- **没沉下去的，就让它自然淘汰。**

## 5. 反馈：模型自报一个 bool，累积成数值

原话：「就是你卡送给模型，模型自己反馈这轮有没有帮助，就一个 bool 值，有就留，没有直接抛，这个是积累一个数值，你懂吧，也不是一次否定。」

- 反馈的来源是**模型自己**：这张卡**在这一轮**有没有帮上忙。**一个 bool。**
- 每次把卡送出去都收一次，**累积成一个数值**（不是只判一次、也不是判一次就定终身）。
- **单次「没有」不构成否定**，不据此淘汰；淘汰走 §4 的时间口径。

## 6. 留坑（所有者说先留着，不许现在填）

1. **底层「更合适的表达方式」。** 到底层不能再是「抽卡片并入提示词」，要用更合适的方式体现学习成果。**具体是什么，先留坑。**
2. **Agent 学习内部的底层联动。** 例如 tool 学习 ↔ 提示词学习 ↔ 工作流学习 之间的联动。**先留坑。**
3. **活跃层的进化。** **先留坑。**
