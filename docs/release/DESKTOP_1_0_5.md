# Desktop 1.0.5 — 修复原生工具服务无法启动

Windows 原生 Desktop 把 Tauri 扩展路径直接传给 Node 脚本入口，导致 `EISDIR: lstat 'D:'`，工具、手机连接和桌宠依赖的服务无法就绪。本版只规范化脚本入口路径，保留可执行文件路径和原有权限、审批、沙箱边界。

14 项 Rust 路径/解析测试通过；随包 Node 的 GUI 父进程对照证明原路径失败、修复后 ready。真实原生 1.0.5 的 Service Host 自动启动并持续运行 35 秒，原错误消失。安装包/便携 ZIP 的 CRC、完整资源和原生 EXE 绑定均通过。

默认旧 CLI，可在设置切换随包新版并切回；CoWork 后台继续独立。CLI 和前端资源沿用 1.0.4 的已验证字节。本轮还复核了权限模式、旧→新→旧→新、旧 CLI 的批准/拒绝/读写搜索，以及后台网关和二维码生成；使用本地模拟 provider，无真实模型或手机真机验收。

Android 1.6.0 为原有签名 APK，未重新编译，与桌面分开提供。桌面仍为未签名预览版，旧 CLI 的 Bash 需要本机 Git for Windows；安装向导、任意原生输入与真实模型任务未据此宣称通过。
