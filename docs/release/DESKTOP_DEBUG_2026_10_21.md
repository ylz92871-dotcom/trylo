# Desktop 调试小报告（2026-10-21）

本轮定位并修复 Service Host 前端生命周期竞态，源码提交为 `10549420`。2026-10-22 完成独立诊断版的原生启动、故障恢复与正常关窗检查。已提交的参赛材料和 GitHub Desktop 1.0.5 成品保持原有字节；诊断版通过不等同于已发布安装包已更新，也不代表所有工具安装成功。

## 问题与影响

| 复现场景 | 修复前实际结果 | 修复处理 |
| --- | --- | --- |
| 两个调用方同时订阅服务帧 | 注册两份监听，停止时残留一份 | 合并进行中的订阅，只有一个活动监听 |
| 停止后，迟到的订阅才注册完成 | 停止后仍接收 ready 等事件 | 用生命周期编号隔离旧回调，迟到的监听立即注销 |
| 服务退出，仍有请求等待响应 | 请求继续等满默认 30 秒 | 收到真实 exit 事件后立即以 NOT_CONNECTED 拒绝在途请求 |
| 崩溃检查的 status 在 stop 后返回 | 再次安排重启，服务在停止后被拉起 | 停止使旧检查失效，只有活动生命周期能发起恢复 |
| 自动重启正在等原生 spawn 时停止 | stop 提前完成，后续 spawn 又留下运行中的服务 | 自动恢复与显式启动共用在途启动记录，stop 等待后再终止 |
| 同时收到两个崩溃通知 | 启动两次恢复，额外消耗恢复预算 | 合并连接检查和恢复启动 |
| 原生 stop 命令失败 | 监听和请求未清理 | 在 finally 中清理客户端，并保留原生失败结果 |

这批问题可能表现为停止后服务复活、重复状态事件，以及宿主退出后操作仍显示等待。它们是时序问题，不改变工具权限、审批策略或沙箱边界。

## 修改范围

- `desktop/src/services-host/service-manager.ts`：活动生命周期、启动/停止顺序、单次连接检查、失败清理。
- `desktop/src/services-host/services-client.ts`：订阅合并、旧事件隔离、宿主退出时拒绝在途请求。
- `desktop/src/services-host/lifecycle-races.test.ts`：7 项原始失败复现，以及取消旧订阅后重新启动、停止期间发起新启动的 2 项边界测试。
- `desktop/src/services-host/service-manager.test.ts`：恢复预算测试从真正启动后的服务开始，并断言三次延迟恢复与耗尽后的 down 通知。修正原测试在未启动服务时直接发送请求、无实际调用地切换失败标记的安排。

## 新发现与未覆盖项

- 工具页仍有 Windows-MCP、KiCad、嘉立创 EDA 的 `install_failed`，若干 CAD 适配器在关窗前显示安装中。故障注入和交互过程中存在安装活动，本轮没有独立复现安装失败原因，也没有把它们归因为权限或网络。本项需要单独收集安装错误并验证恢复，不能算作本轮修复通过。
- 关窗日志还暴露了桌宠清理范围问题：`desktop/src-tauri/src/commands/shutdown.rs::kill_companion_by_image` 无条件执行按镜像名的全局清理。桌宠服务源码又允许多个客户端共用，存在关闭一个实例影响其他实例桌宠的风险。本轮没有启动桌宠，没有观察到实际误杀；这项源码风险尚未修复或完成跨实例验收，需要单列处理，不能混入生命周期通过结论。
